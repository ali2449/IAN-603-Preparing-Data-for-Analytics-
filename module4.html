Aggregation habit

State the question → choose one output-row grain → define measures → filter rows → filter groups → validate against detail.

Learning Objectives

By the end of this module, you will be able to:

  1. Use COUNT, SUM, AVG, MIN, and MAX and explain how NULL values affect their results.
  2. Define the grain of an output and use GROUP BY with one or more grouping columns.
  3. Combine WHERE, GROUP BY, HAVING, and ORDER BY in the correct logical sequence.
  4. Create conditional counts and sums with CASE and PostgreSQL's aggregate FILTER clause.
  5. Produce targeted subtotals with GROUPING SETS, hierarchical summaries with ROLLUP, and multidimensional summaries with CUBE.
  6. Use GROUPING() to distinguish subtotal placeholders from ordinary NULL values.
  7. Apply window functions to rank rows, add group context, compute shares, and calculate running totals without collapsing detail rows.
  8. Run PostgreSQL-compatible aggregation queries in the embedded lab and interpret result tables and errors.

The Five-Step Aggregation Workflow

1. AskState the decision question.
2. Set grainDefine one output row.
3. MeasureChoose counts, totals, or averages.
4. FilterSeparate row and group filters.
5. ValidateCompare summaries with detail.

Summary Functions: Many Rows to One Result

Aggregate functions reduce a set of input rows to a summary value.

COUNT

Counts rows, non-NULL values, or distinct non-NULL values.

SUM

Adds numeric values, such as units or revenue.

AVG

Computes the arithmetic mean of non-NULL numeric values.

MIN

Returns the smallest value in the input set.

MAX

Returns the largest value in the input set.

COUNT Has Three Common Meanings

Comparison of COUNT forms in PostgreSQL
ExpressionWhat it countsImportant behavior
COUNT(*)All input rowsCounts a row even when one or more columns contain NULL.
COUNT(column)Rows where that column is not NULLUseful for measuring completeness or completed events.
COUNT(DISTINCT column)Unique non-NULL valuesAnswers questions such as “How many different patients?”
 
SELECT COUNT(*) AS all_admissions,
       COUNT(discharge_time) AS completed_admissions,
       COUNT(DISTINCT subject_id) AS unique_patients
FROM admissions;

PostgreSQL Length-of-Stay Calculation

The source lesson uses DATEDIFF, which is not PostgreSQL syntax. In PostgreSQL, subtracting one timestamp from another returns an interval. Converting that interval to epoch seconds and dividing by 86,400 produces fractional days.

SELECT ROUND(
           (AVG(EXTRACT(EPOCH FROM (discharge_time - admit_time)) / 86400.0))::numeric,
           2
       ) AS average_stay_days
FROM admissions
WHERE discharge_time IS NOT NULL;
Interpretation check: AVG ignores NULL expressions. Ongoing admissions with no discharge_time therefore do not contribute to the average. Report the completed-admission count beside the average when sample size matters.

GROUP BY and the Grain of the Result

GROUP BY decides what one output row represents.

1

Detail grain

One row per admission. No grouping is needed.

2

Category grain

One row per diagnosis or sales category.

3

Multi-column grain

One row per patient-and-diagnosis combination.

Core rule: In a grouped query, every selected expression must either be aggregated, appear in the GROUP BY list, or be functionally dependent in a way PostgreSQL can prove. For introductory work, use the simpler rule: selected non-aggregate columns belong in GROUP BY. 
SELECT diagnosis,
       COUNT(*) AS admission_count
FROM admissions
GROUP BY diagnosis
ORDER BY admission_count DESC, diagnosis;

Grouping by More Than One Column

Adding a grouping column makes the result more granular. The query below returns one row for each patient-and-diagnosis combination, not one row per patient and not one row per diagnosis.

SELECT subject_id,
       diagnosis,
       COUNT(*) AS admission_count
FROM admissions
GROUP BY subject_id, diagnosis
ORDER BY subject_id, diagnosis;

A Useful Error

Run the following query to see PostgreSQL protect you from an ambiguous result. Which subject_id should represent an entire diagnosis group? The query does not define that.

-- Expected result: PostgreSQL rejects subject_id because it is
-- neither aggregated nor included in GROUP BY.
SELECT diagnosis, subject_id, COUNT(*) AS admission_count
FROM admissions
GROUP BY diagnosis;

WHERE Filters Rows; HAVING Filters Groups

Place each condition at the stage where the needed value exists.

Comparison of WHERE and HAVING
QuestionWHEREHAVING
What is filtered?Individual source rowsGroups produced by aggregation
When does it run?Before GROUP BYAfter GROUP BY
Can it use an aggregate?Not at the same query levelYes, such as COUNT(*) > 1
Typical questionAdmissions after April 1Diagnoses with multiple admissions

Complete Aggregation Pattern

FROM
Choose the source table or joined rows.
WHERE
Remove source rows that should not enter the calculation.
GROUP BY
Define the output grain.
HAVING
Remove summary groups that do not meet an aggregate condition.
SELECT
Return grouping columns and computed measures.
ORDER BY
Present the summaries in a useful order.
SELECT category,
       SUM(quantity) AS units_sold,
       SUM(quantity * price) AS category_revenue
FROM sales
WHERE price >= 25
GROUP BY category
HAVING SUM(quantity) > 10
ORDER BY category_revenue DESC;
Efficiency principle: Put row-level conditions in WHERE rather than HAVING so fewer rows reach the grouping stage. Use HAVING only when the condition depends on a group result.

Conditional Aggregation

Calculate several filtered metrics in one grouped query.

Portable Pattern: Aggregate a CASE Expression

A CASE expression converts a condition into values that an aggregate can summarize. The pattern below produces separate pneumonia and fracture counts for every patient.

SELECT subject_id,
       SUM(CASE WHEN diagnosis = 'Pneumonia' THEN 1 ELSE 0 END) AS pneumonia_admissions,
       SUM(CASE WHEN diagnosis = 'Fracture' THEN 1 ELSE 0 END) AS fracture_admissions
FROM admissions
GROUP BY subject_id
ORDER BY subject_id;

PostgreSQL Pattern: Aggregate FILTER

PostgreSQL also supports FILTER (WHERE ...), which states the condition directly on each aggregate. It is often easier to read when a report contains many conditional metrics.

SELECT subject_id,
       COUNT(*) FILTER (WHERE diagnosis = 'Pneumonia') AS pneumonia_admissions,
       COUNT(*) FILTER (WHERE diagnosis = 'Fracture') AS fracture_admissions
FROM admissions
GROUP BY subject_id
ORDER BY subject_id;
Use CASE when

You need broad cross-dialect portability or want to map conditions to values other than a simple inclusion test.

Use FILTER when

You are writing PostgreSQL and want concise, independently filtered aggregates.

Advanced Grouping: GROUPING SETS, ROLLUP, and CUBE

Generate multiple summary grains in one statement instead of stacking many queries with UNION ALL.

Comparison of PostgreSQL advanced grouping forms
FeatureGenerated groupingsBest use
GROUPING SETSOnly the combinations you listCustom report levels
ROLLUP(A, B)(A,B), (A), and ()Hierarchical detail, subtotal, and grand total
CUBE(A, B)(A,B), (A), (B), and ()All combinations of analytical dimensions
Code 0

Both expressions participate: ordinary category-and-product detail.

Code 1 or 2

One expression is rolled up: a subtotal at another grain.

Code 3

Neither expression participates: the grand-total row.

Do not label totals with COALESCE alone: subtotal columns appear as NULL, but source data can also contain a real NULL. GROUPING(column) tells you whether NULL is a subtotal placeholder. 

SELECT
    CASE WHEN GROUPING(category) = 1 THEN 'All categories' ELSE category END AS category_label,
    CASE WHEN GROUPING(product) = 1 THEN 'All products' ELSE product END AS product_label,
    SUM(sales) AS total_sales,
    GROUPING(category, product) AS grouping_code
FROM product_sales
GROUP BY ROLLUP(category, product)
ORDER BY GROUPING(category), category, GROUPING(product), product;

SELECT
    CASE WHEN GROUPING(category) = 1 THEN 'All categories' ELSE category END AS category_label,
    CASE WHEN GROUPING(product) = 1 THEN 'All products' ELSE product END AS product_label,
    SUM(sales) AS total_sales,
    GROUPING(category, product) AS grouping_code
FROM product_sales
GROUP BY CUBE(category, product)
ORDER BY GROUPING(category), category, GROUPING(product), product;

SELECT
    CASE WHEN GROUPING(category) = 1 THEN 'All categories' ELSE category END AS category_label,
    CASE WHEN GROUPING(product) = 1 THEN 'All products' ELSE product END AS product_label,
    SUM(sales) AS total_sales
FROM product_sales
GROUP BY GROUPING SETS ((category), (product), ())
ORDER BY GROUPING(category), category, GROUPING(product), product;

Window Functions: Summaries Without Collapsing Rows

Window functions keep each detail row while adding calculations across related rows.

Comparison of GROUP BY and window functions
BehaviorGROUP BYWindow function
Number of result rowsOne row per groupUsually one row per input row
Group definitionGROUP BYPARTITION BY inside OVER()
Ordering inside calculationNot inherently definedORDER BY inside OVER()
Typical useSummary reportRank, running total, comparison with group average

Rank Within Each Department

SELECT name,
       department,
       salary,
       RANK() OVER (
           PARTITION BY department
           ORDER BY salary DESC
       ) AS department_rank
FROM employees
ORDER BY department, department_rank, name;

Show Department and Company Context on Every Row

SELECT name,
       department,
       salary,
       ROUND(AVG(salary) OVER (PARTITION BY department), 2) AS department_average,
       ROUND(AVG(salary) OVER (), 2) AS company_average
FROM employees
ORDER BY department, salary DESC;

Logical Execution Order and Dialect Portability

Understanding when each clause is evaluated explains both correct syntax and common errors.

FROM / JOIN
→
WHERE
→
GROUP BY
→
HAVING
→
SELECT
→
WINDOW
→
ORDER BY
→
LIMIT
  • WHERE cannot use a same-level aggregate because grouping has not occurred yet.
  • HAVING can test aggregates because groups already exist.
  • Window functions see the rows that remain after grouping and HAVING.
  • ORDER BY can usually refer to a selected alias because sorting occurs late.

SELECT city,
       AVG(satisfaction_score) AS average_score

Move from recognition to construction and then to analytical explanation.

Find diagnoses with more than one admission and sort the largest group first.

Source Assessment Tasks, Made Runnable

  1. Using sales, return total revenue and unique products per category. Keep categories whose total quantity exceeds 10 and sort by revenue descending.
  2. Using grades, find each course's average grade in Fall 2024, but only when at least 50 students are enrolled.
  3. Using admissions, return separate pneumonia and fracture counts for each patient.
  4. Using employees, show department averages and the overall company average in one result set.

Sales solution

-- Find total revenue and unique products by category.
-- Keep only categories whose total quantity is greater than 10.
-- Sort highest revenue first.

SELECT category,
       SUM(quantity * price) AS total_revenue,
       COUNT(DISTINCT product) AS unique_products,
       SUM(quantity) AS total_quantity
FROM sales
GROUP BY category
HAVING SUM(quantity) > 10
ORDER BY total_revenue DESC;

Grades solution

SELECT course,
       ROUND(AVG(grade), 2) AS average_grade,
       COUNT(*) AS enrollment
FROM grades
WHERE semester = 'Fall 2024'
GROUP BY course
HAVING COUNT(*) >= 50
ORDER BY average_grade DESC;

Conditional admissions solution

SELECT subject_id,
       COUNT(*) FILTER (WHERE diagnosis = 'Pneumonia') AS pneumonia_admissions,
       COUNT(*) FILTER (WHERE diagnosis = 'Fracture') AS fracture_admissions
FROM admissions
GROUP BY subject_id
ORDER BY subject_id;

Department and company solution

SELECT
    CASE WHEN GROUPING(department) = 1 THEN 'Company overall' ELSE department END AS scope,
    ROUND(AVG(salary), 2) AS average_salary,
    COUNT(*) AS employees
FROM employees
GROUP BY GROUPING SETS ((department), ())
ORDER BY GROUPING(department), department;

Assessment and Closure

Module Challenge

Create one query for a decision-maker that answers:

Which sales categories generated meaningful revenue, and how much did each qualifying category contribute?

Your query must include:

  • A stated output grain of one row per category
  • At least two aggregate measures
  • A source-row condition in WHERE
  • A group condition in HAVING
  • A descending analytical sort
  • A two-sentence interpretation that distinguishes row filters from group filters

Key Takeaways

Grain before syntax

Know what one output row represents before choosing grouping columns.

NULL changes counts

COUNT(*) and COUNT(column) intentionally answer different questions.

Filter at the right stage

WHERE filters source rows; HAVING filters computed groups.

Windows preserve detail

Use OVER() when each original row must remain visible with analytical context.

Glossary

Aggregate

A function that produces one result from a set of input values.

Grain

The real-world meaning of one row in a table or result set.

Grouping set

One selected combination of expressions used to form summary groups.

Window

The related rows used by a window function for the current output row.
