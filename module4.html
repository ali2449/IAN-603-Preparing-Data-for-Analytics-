Module 4: SQL Basics II: Aggregations

Learning Objectives

Upon completion of this module, participants will be able to:

  • Utilize SQL aggregate functions (COUNT, SUM, AVG, MIN, MAX) to summarize data.
  • Apply the GROUP BY clause to group rows by one or more columns for aggregation.
  • Use the HAVING clause to filter aggregated results.
  • Combine GROUP BY with WHERE and ORDER BY for comprehensive data analysis.
  • Understand the execution order of SQL clauses when using aggregations.
  • Perform advanced aggregations using GROUPING SETS, CUBE, and ROLLUP.
  • Use SQL Window Functions to perform calculations across a set of rows without collapsing the result set.
  • Execute aggregate queries in cloud-based environments like Microsoft Fabric Lakehouse.

Introduction to SQL Aggregations

Aggregations in SQL allow you to summarize data across multiple rows, transforming detailed records into meaningful insights. This module builds on the SELECT, WHERE, and ORDER BY clauses from Module 3, introducing aggregate functions like COUNT, SUM, AVG, MIN, and MAX. The GROUP BY clause organizes data into groups for aggregation, while HAVING filters those groups. These tools are critical for tasks like calculating total sales, average patient ages, or minimum stock levels in real-world scenarios, such as analyzing healthcare trends in Greensboro, NC, or optimizing a local business's inventory.

Aggregations are widely used across industries. For example, in healthcare, you might calculate the average length of hospital stays per diagnosis; in retail, total sales by product category; in education, average grades by course. Understanding how to combine these functions with filtering and sorting enhances your ability to extract actionable insights from large datasets efficiently.

Aggregate Functions

Aggregate functions process multiple rows to produce a single summary value. Common functions include:

  • COUNT: Counts the number of rows or non-NULL values in a column.
  • SUM: Adds up numeric values in a column.
  • AVG: Calculates the average of numeric values.
  • MIN: Finds the smallest value in a column.
  • MAX: Finds the largest value in a column.

-- Count total admissions
SELECT COUNT(*) AS TotalAdmissions
FROM ADMISSIONS;

-- Count distinct patients
SELECT COUNT(DISTINCT subject_id) AS UniquePatients
FROM ADMISSIONS;

-- Calculate average length of stay (in days)
SELECT AVG(DATEDIFF(day, admit_time, discharge_time)) AS AvgStayDays
FROM ADMISSIONS;

Explanation: COUNT(*) counts all rows, while COUNT(DISTINCT subject_id) counts unique patients. AVG computes the average stay duration, useful for hospital resource planning. Note that DATEDIFF is often used to calculate time intervals in days.

GROUP BY Clause: Grouping Data

The GROUP BY clause groups rows with identical values in specified columns into summary rows, applying aggregate functions to each group.

  • Purpose: Summarize data by categories, e.g., total admissions per diagnosis.
  • Rules: Any column in the SELECT statement that is not an aggregate function must be included in the GROUP BY clause.
-- Count admissions by diagnosis
SELECT diagnosis, COUNT(*) AS AdmissionCount
FROM ADMISSIONS
GROUP BY diagnosis;

-- Average stay by diagnosis
SELECT diagnosis, AVG(DATEDIFF(day, admit_time, discharge_time)) AS AvgStayDays
FROM ADMISSIONS
GROUP BY diagnosis;

-- Grouping by multiple columns (e.g., patient and diagnosis)
SELECT
    subject_id,
    diagnosis,
    COUNT(*) AS AdmissionCount
FROM
    ADMISSIONS
GROUP BY
    subject_id,
    diagnosis;

Explanation: The first query counts admissions per diagnosis, the second calculates average stay length. The third example shows how you can group by multiple columns to get a more granular breakdown, in this case, the number of times each patient had a specific diagnosis.

HAVING Clause: Filtering Groups

The HAVING clause filters grouped results, applied after GROUP BY, unlike WHERE which filters individual rows before aggregation. This is the key difference: WHERE operates on rows, and HAVING operates on groups.

  • Use Case: Filter groups based on aggregate values, e.g., only diagnoses with more than 5 admissions.
  • Syntax: HAVING condition, using aggregates like COUNT(*) > 5.
-- Diagnoses with more than one admission
SELECT diagnosis, COUNT(*) AS AdmissionCount
FROM ADMISSIONS
GROUP BY diagnosis
HAVING COUNT(*) > 1;

-- Diagnoses with average stay > 5 days
SELECT diagnosis, AVG(DATEDIFF(day, admit_time, discharge_time)) AS AvgStayDays
FROM ADMISSIONS
GROUP BY diagnosis
HAVING AVG(DATEDIFF(day, admit_time, discharge_time)) > 5;

Explanation: HAVING filters groups, e.g., only showing diagnoses with multiple admissions or long average stays. Note that in many SQL dialects, you cannot use an alias like `AvgStayDays` in the `HAVING` clause, so you must repeat the full aggregate function.

Expanded Example (High-Value Categories):

-- Categories with total revenue > 1000
SELECT category, SUM(quantity * price) AS CategoryRevenue
FROM Sales
GROUP BY category
HAVING SUM(quantity * price) > 1000;

Explanation: This identifies high-performing categories for targeted marketing. Notice how the `HAVING` clause filters the results of the `SUM` function.

Aggregations with CASE Statements

Combining aggregate functions with CASE statements allows you to perform conditional counts and sums. This is extremely useful for analyzing data based on specific conditions without needing multiple queries or complex joins.

-- Count the number of sales for each category and a count of high-value sales (> $100)
SELECT
    category,
    COUNT(*) AS TotalSales,
    SUM(CASE WHEN price > 100 THEN 1 ELSE 0 END) AS HighValueSales
FROM
    Sales
GROUP BY
    category;

Explanation: This query calculates the total number of sales per category and, within the same query, counts how many of those sales were for products priced over $100. The CASE statement acts like a conditional counter within the `SUM` function.

Advanced Aggregation Techniques

For more complex reporting and data analysis, SQL provides advanced aggregation features that can generate multiple grouping combinations in a single query, significantly simplifying your code.

GROUPING SETS, CUBE, and ROLLUP

  • GROUPING SETS: Generates a result set equivalent to the union of two or more `GROUP BY` queries. This allows you to report on multiple levels of aggregation in one go.
  • ROLLUP: A shorthand for `GROUPING SETS` that generates subtotals for the hierarchy specified and a grand total. It follows a top-down approach. For example, `ROLLUP(A, B)` generates grouping sets for `(A, B)`, `(A)`, and `()`.
  • CUBE: An even more powerful shorthand that generates subtotals for all possible combinations of the specified columns. For `CUBE(A, B)`, it generates grouping sets for `(A, B)`, `(A)`, `(B)`, and `()`.
-- Using ROLLUP to get subtotals for category and a grand total
SELECT
    category,
    SUM(quantity * price) AS TotalRevenue
FROM
    Sales
GROUP BY ROLLUP(category);

-- Using GROUPING SETS for specific combinations
SELECT
    category,
    diagnosis,
    COUNT(*) AS Total
FROM
    ADMISSIONS
GROUP BY GROUPING SETS (
    (category),
    (diagnosis),
    ()
);

Explanation: The first query uses `ROLLUP` on the `Sales` table to produce a result that shows the revenue per category and a total revenue for all categories. The second query uses `GROUPING SETS` on a hypothetical combined table to show counts grouped by category, by diagnosis, and a grand total.

SQL Window Functions

Window functions perform a calculation across a set of table rows that are somehow related to the current row. This is different from aggregate functions because they do not group rows together and collapse them into a single output row. Instead, they produce a result for each row in the original table.

  • Syntax: A window function is called with the OVER() clause. This clause defines the "window" of rows on which the function operates.
  • PARTITION BY: Divides the rows into groups for the function to operate on (similar to `GROUP BY`, but without collapsing the rows).
  • ORDER BY: Orders the rows within each partition.
-- Ranking employees by salary within each department
SELECT
    name,
    department,
    salary,
    RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS DepartmentRank
FROM
    Employees;

-- Calculating the average salary for each department
SELECT
    name,
    department,
    salary,
    AVG(salary) OVER (PARTITION BY department) AS AvgDepartmentSalary
FROM
    Employees;

Explanation: The first query uses `RANK()` to assign a rank to each employee based on their salary, but the ranking is reset for each `department`. The second query shows each employee's salary alongside the average salary for their entire department, demonstrating how the window function can provide contextual information without changing the number of rows.

Order of Execution

SQL executes clauses in a specific, logical order. Understanding this order is crucial for writing correct and efficient queries. The sequence is:

  1. FROM: Determines the data source.
  2. WHERE: Filters individual rows from the `FROM` table.
  3. GROUP BY: Groups the filtered rows into summary groups.
  4. HAVING: Filters the groups created by `GROUP BY`.
  5. SELECT: Selects the final columns, including aggregated values. This is where window functions are calculated.
  6. ORDER BY: Sorts the final result set.

A key takeaway is that WHERE cannot filter on aggregated values because it runs before aggregation occurs. Only HAVING can filter on the results of aggregate functions.

-- Valid: Filter groups with HAVING
SELECT diagnosis, COUNT(*) AS AdmissionCount
FROM ADMISSIONS
GROUP BY diagnosis
HAVING COUNT(*) > 1;

-- Invalid: Can't use aggregate in WHERE
-- SELECT diagnosis, COUNT(*) FROM ADMISSIONS WHERE COUNT(*) > 1 GROUP BY diagnosis; -- Error

Explanation: The invalid query fails because WHERE tries to evaluate `COUNT(*)` on individual rows, which is not possible. The `HAVING` clause, running after `GROUP BY`, correctly performs this filtering on the aggregated results.

Running Aggregations in Microsoft Fabric Lakehouse

In Microsoft Fabric, aggregations are executed on large-scale data lakes using SQL endpoints or notebooks, leveraging distributed computing for efficiency. The syntax remains the same, but the performance is optimized for massive datasets. The principles of aggregation are universal, whether you're working with a small local database or a large-scale cloud environment.

-- Aggregate survey data in Fabric
SELECT city, AVG(satisfaction_score) AS AvgScore
FROM survey_lakehouse.Responses
WHERE response_date >= '2025-01-01'
GROUP BY city
HAVING COUNT(*) > 100
ORDER BY AvgScore DESC;

Explanation: This aggregates survey scores by city for recent responses, filtering for significant sample sizes. This query demonstrates how the aggregation skills you've learned apply directly to big data analytics platforms.
