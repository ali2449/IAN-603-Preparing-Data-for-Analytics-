Boolean operators

Three operators build most compound rules

AND

All connected conditions must be TRUE.

Usually narrows a cohort.

OR

At least one connected condition must be TRUE.

Usually broadens a cohort.

NOT

Negates a known Boolean state.

NOT UNKNOWN remains UNKNOWN.

Important: SQL also has UNKNOWN, so Boolean logic is not always just TRUE and FALSE.
Boolean logic

AND requires every connected condition

Each additional requirement can remove rows from the result.

Active

Age

Severity

NULL logic

SQL conditions can be TRUE, FALSE, or UNKNOWN

TRUEThe condition is satisfied.
FALSEThe condition is not satisfied.
UNKNOWNThe available data cannot decide.
WHERE rule: only TRUE rows are retained.

NULL logic

Ordinary comparison cannot test a missing value

Incorrect

Produces UNKNOWN.

Correct

email_address IS NULL

Produces TRUE or FALSE.

Rule: use IS NULL or IS NOT NULL for missing-value tests.

NULL-safe comparison

Compare nullable values without producing UNKNOWN

IS DISTINCT FROM

TRUE when values differ, including one NULL versus one non-NULL.

IS NOT DISTINCT FROM

TRUE when values match, including NULL versus NULL.

Key behavior: these predicates return TRUE or FALSE, never UNKNOWN.

NULL-handling tools

NULLIF(a, b) returns NULL when a and b compare equal.

Useful text pattern

Conditional transformation

CASE evaluates rules from top to bottom

1 EvaluateCheck the first WHEN.
2 StopUse the first TRUE branch.
3 ReturnProduce its THEN value.
4 DefaultUse ELSE, or NULL if omitted.
First match wins. Branch order is part of the business rule.

Common traps

A NULL inside NOT IN can turn apparent non-matches into UNKNOWN

The database cannot prove that a value is different from an unknown list element.

Safer: remove NULL from the list and handle missing status explicitly.
