Best installation habit

Choose one local PostgreSQL server installation method. Multiple local servers are a common cause of port and PATH conflicts.

Platform setup

Windows: EDB interactive installer

The official PostgreSQL Windows download page points to the EDB interactive installer. It bundles the PostgreSQL server, pgAdmin, and StackBuilder.

  1. Open the official Windows download page.
    PostgreSQL Windows downloads. Choose the EDB interactive installer and select the current stable PostgreSQL major unless your instructor specifies another supported version.
  2. Run the installer.
    Keep PostgreSQL Server, pgAdmin 4, and Command Line Tools selected. StackBuilder is optional for this course.
  3. Set the database superuser password.
    The installer normally creates the administrative role postgres. Save its password securely; pgAdmin may ask for it when you connect.
  4. Keep the default port unless you have a conflict.
    The standard PostgreSQL port is 5432. If the installer says it is already in use, check whether PostgreSQL is already installed before choosing another port.
  5. Finish the installation and open pgAdmin 4.
    You can skip optional StackBuilder packages unless a later course activity explicitly needs an extension or driver.

Verify from Windows

psql --version

If Windows says psql is not recognized, open SQL Shell (psql) from the Start menu or add the PostgreSQL bin directory (typically C:\Program Files\PostgreSQL\<major>in) to your PATH.

Typical local connection: host localhost, port 5432, maintenance database postgres, username postgres.
Platform setup

macOS: Postgres.app or Homebrew

Option A · Postgres.app

Recommended for simplicity

  1. Download Postgres.app from its official site.
  2. Move it to Applications and open it.
  3. Click Initialize if prompted to create a server cluster.
  4. Add the bundled command-line tools to PATH if you want to use psql in Terminal.

Option B · Homebrew

Terminal workflow

Use this when you already use Homebrew and are comfortable managing services from Terminal.

brew update
brew install postgresql@18
brew services start postgresql@18
brew services list
psql postgres

Postgres.app command-line PATH

The Postgres.app documentation recommends adding its current version's bin directory to the macOS path list:

sudo mkdir -p /etc/paths.d
echo /Applications/Postgres.app/Contents/Versions/latest/bin | sudo tee /etc/paths.d/postgresapp

Open a new Terminal window afterward and verify:

psql --version
psql postgres
Important: Postgres.app and Homebrew can each run their own PostgreSQL server. Pick one for the course to avoid port 5432 conflicts.
Platform setup

Ubuntu / Debian: APT

PostgreSQL is available directly from Ubuntu and Debian repositories. The PostgreSQL Global Development Group (PGDG) also maintains an APT repository that provides supported PostgreSQL majors, including the current major.

Path A · Distribution package

Use this if you want the version provided and maintained by your Linux distribution:

sudo apt update
sudo apt install -y postgresql
sudo systemctl status postgresql

Path B · PGDG repository for PostgreSQL 18

Use the official PGDG repository if you specifically want PostgreSQL 18 on a supported Ubuntu/Debian release:

sudo apt install -y postgresql-common ca-certificates
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh
sudo apt update
sudo apt install -y postgresql-18

Connect locally

Debian-family packages commonly let the operating-system postgres account connect locally using peer authentication:

sudo -u postgres psql

Inside psql, you can verify the connection with:

SELECT version();
SELECT current_database(), current_user;
pgAdmin note: A local shell connection may work without a database password because Linux can use peer authentication. pgAdmin uses a network-style connection, so authentication requirements can differ.
Platform setup

RHEL / Rocky / AlmaLinux / Fedora: DNF

Red Hat-family distributions include PostgreSQL packages, and the PostgreSQL project also provides the PGDG Yum repository for supported major versions.

Path A · Distribution package

sudo dnf install -y postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable postgresql.service
sudo systemctl start postgresql.service

Path B · PGDG repository

Because the repository setup RPM depends on your exact distribution release and architecture, use the PostgreSQL project's selector rather than copying a hard-coded repository URL from an old guide:

PostgreSQL Red Hat-family download selector

After configuring the PGDG repository for PostgreSQL 18, the versioned package/service pattern is typically:

sudo dnf install -y postgresql18-server
sudo /usr/pgsql-18/bin/postgresql-18-setup initdb
sudo systemctl enable --now postgresql-18

Then connect locally as the PostgreSQL operating-system account:

sudo -u postgres psql
Fedora note: Fedora changes quickly. For a course laptop, use packages supported by your current Fedora release and avoid copying commands designed for an older Fedora version.

Verification

Verify PostgreSQL before the first SQL assignment

Do not stop at “the installer finished.” Verify the client, the server, the connection, and your ability to create/query a database.

1 · Client version

psql --version

2 · Server connection

SELECT version();
SELECT current_database() AS database_name,
       current_user AS connected_as;

3 · Create a course database

Run this once while connected with a role that has permission to create databases:

CREATE DATABASE ian603;

4 · Run a small course readiness test

Connect to ian603 in pgAdmin or psql, then run:

CREATE TABLE installation_check (
    check_id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    message text NOT NULL,
    checked_at timestamptz NOT NULL DEFAULT now()
);

INSERT INTO installation_check (message)
VALUES ('PostgreSQL is ready for IAN 603');

SELECT *
FROM installation_check;

If this returns one row, you have confirmed DDL, DML, default values, identity columns, and query execution.

Success condition: You can start PostgreSQL, connect, execute SQL, and see the inserted row in ian603.
Troubleshooting

Common installation problems

psql not found

PostgreSQL may be installed but its command-line tools are not in your PATH.

Check: use the platform's installed SQL shell, or add the PostgreSQL bin directory to PATH.

Connection refused

The server may not be running, or pgAdmin may be using the wrong port.

Check: service status and whether PostgreSQL is listening on 5432.

Password authentication failed

Make sure you are using a PostgreSQL role and its database password—not necessarily your operating-system account password.

Linux: local peer authentication and pgAdmin password authentication can behave differently.

Port 5432 already in use

You may already have a PostgreSQL server running.

Do not immediately install a second server. Identify the existing service first.

macOS:

lsof -i :5432
brew services list

Linux:

ss -ltnp | grep 5432
systemctl status postgresql

Windows Command Prompt:

netstat -ano | findstr :5432

pg_isready -h localhost -p 5432

If pg_isready is available, it reports whether a PostgreSQL server is accepting connections at that host and port.

Safe local setup

Security basics for a course installation

Keep it local

For IAN 603, a local database should normally listen only for local connections. You do not need to expose PostgreSQL directly to the public internet.

Protect credentials

Use a unique password when one is required. Do not place passwords in SQL scripts, screenshots, Git repositories, or Canvas posts.

Limit superuser use

The postgres superuser is convenient for local administration, but application-style work should normally use a less-privileged role.

Keep minor releases current

PostgreSQL recommends running the current minor release for your supported major version because minor releases include bug and security fixes.

Do not weaken authentication just to make a connection error disappear. Avoid changing PostgreSQL to broad trust authentication or opening listen_addresses to all networks unless you understand the security impact and have an explicit reason.
