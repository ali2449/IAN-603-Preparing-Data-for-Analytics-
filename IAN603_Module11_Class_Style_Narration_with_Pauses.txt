Slide 2: What advanced SQL is really doing

Advanced SQL is mostly about controlling intermediate results and row context.

[pause=0.7]

A CTE gives a meaningful name to a stage in the query.

[pause=0.8]

A window function lets one row see related rows without automatically collapsing the result.

[pause=0.7]

Sequence functions depend on a meaningful order.

Slide 6: The grain rule still applies

Grain remains the central safety rule.

[pause=0.7]

A CTE can have a different grain from the source table.

[pause=0.7]

A window function usually preserves the current row grain.

[pause=0.7]

A later filter can reduce the number of rows without changing what one row represents.

[pause=0.7]

Slide 7: CTE mental model

A Common Table Expression begins with WITH.

[pause=0.7]

Think of it as a named intermediate relation inside one statement.

[pause=0.7]

The first stage can summarize or clean the source.

[pause=0.7]

A later stage can join or enrich that result.

[pause=0.7]

The final SELECT consumes the prepared data.

[pause=0.7]

Naming the stages helps you reason about the transformation one step at a time.

[pause=1.0]

Slide 8: CTE syntax anatomy

A CTE has a simple structure.

[pause=0.7]

WITH gives the stage a name.

[pause=0.7]

The query inside the parentheses defines the rows and columns of that stage.

[pause=0.8]

The final query can read the CTE by name.

[pause=0.8]

You can also define several CTEs separated by commas.

[pause=0.7]

The CTE is not a permanent table. It belongs to the statement.

[pause=1.0]

Slide 9: When a CTE helps

A CTE is useful when one stage deserves a name.

[pause=0.7]

It can make a multi-step query easier to read.

[pause=0.8]

It is especially helpful when you need to calculate a window value first and filter that result later.

[pause=0.7]

Recursive queries also use the CTE structure.

[pause=0.7]

Use a CTE because it clarifies the logic, not simply because the query is long.

[pause=1.0]

Slide 10: When a CTE does not help

CTEs are not automatically better.

[pause=0.7]

A short query may be clearer without one.

[pause=0.8]

A CTE also does not repair unclear grain.

[pause=0.7]

And it does not automatically make a query faster.

[pause=0.8]

Use named stages when they improve reasoning and maintainability.

[pause=1.0]

Slide 16: CTEs and performance

CTEs are mainly a query-organization tool.

[pause=0.8]

PostgreSQL can sometimes inline or fold a non-recursive CTE into the surrounding query.

[pause=0.8]

In other situations, materialization behavior can matter.

[pause=0.7]

The practical lesson for this course is simple: use CTEs for clarity, and inspect the execution plan when performance matters.

[pause=0.8]

Do not assume WITH automatically makes a query faster.

[pause=1.0]

Slide 18: Recursive CTEs

A recursive CTE has two parts.

[pause=0.7]

The anchor term starts the result.

[pause=0.7]

The recursive term refers to the CTE and finds the next level.

[pause=0.7]

UNION ALL combines the rows.

[pause=0.7]

The process continues until the recursive term produces no more matching rows.

[pause=0.7]

This is useful for hierarchies and parent-child structures.

[pause=1.0]

Slide 19: Anchor vs recursive term

When reading recursion, identify the anchor first.

[pause=0.7]

Then identify the self-reference.

[pause=0.7]

The join condition defines how one level connects to the next.

[pause=0.7]

Adding a depth or path column can make the traversal much easier to inspect and debug.

[pause=0.8]

Do not try to understand the whole recursive statement at once.

[pause=1.0]

Slide 24: Window functions

Window functions are powerful because they preserve row detail.

[pause=0.7]

GROUP BY usually reduces multiple rows to one grouped row.

[pause=0.7]

A window function can calculate a group average, rank, running total, or previous value while still returning the individual row.

[pause=0.8]

This is why windows are ideal when you need both detail and context in the same result.

[pause=1.0]

Slide 25: OVER clause anatomy

A window expression has up to four important pieces.

[pause=0.7]

The function tells us what is calculated.

[pause=0.7]

PARTITION BY defines independent groups.

[pause=0.7]

ORDER BY defines sequence.

[pause=0.7]

The frame determines which ordered rows participate in some window calculations.

[pause=0.7]

When a window query is confusing, identify these pieces separately.

[pause=1.0]

Slide 27: PARTITION BY

PARTITION BY divides rows into independent window groups.

[pause=0.7]

Without a partition, the window can operate over all rows.

[pause=0.7]

With department partitioning, calculations restart for each department.

[pause=0.7]

With patient partitioning, sequence calculations restart for each patient.

[pause=0.7]

Partition changes the calculation context, not the number of output rows by itself.

[pause=1.0]

Slide 28: ORDER BY inside OVER

ORDER BY inside OVER is part of the analytical definition.

[pause=0.7]

For ranking, it defines higher and lower positions.

[pause=0.7]

For LAG and LEAD, it defines previous and next.

[pause=0.7]

For running totals, it defines the sequence of accumulation.

[pause=0.8]

When ordering values can tie, add a stable tie-breaker when deterministic row sequence matters.

[pause=1.0]

Slide 29: Window frames

A frame describes which rows within an ordered partition contribute to the current calculation.

[pause=0.7]

For a running total, the frame may start at the beginning and end at the current row.

[pause=0.8]

For a three-row moving average, it may include two preceding rows and the current row.

[pause=0.7]

For some value functions, the frame may need to extend to the end of the partition.

[pause=1.0]

Slide 30: Ranking functions

ROW_NUMBER, RANK, and DENSE_RANK look similar until ties occur.

[pause=0.7]

ROW_NUMBER always assigns a unique sequence.

[pause=0.7]

RANK gives equal values the same rank and leaves gaps afterward.

[pause=0.7]

DENSE_RANK also shares ranks but does not leave gaps.

[pause=0.7]

Choose the function based on what ties should mean for the business question.

[pause=1.0]

Slide 31: ROW_NUMBER

ROW_NUMBER assigns a unique sequence even when values tie.

[pause=0.7]

This makes it useful for selecting exactly the top two or top three rows per group.

[pause=0.7]

But if salaries tie and you only order by salary, the sequence among tied rows may not be deterministic.

[pause=0.7]

Add a stable tie-breaker such as employee ID when the order matters.

[pause=1.0]

Slide 32: RANK

RANK behaves like a competition ranking.

[pause=0.7]

If two employees tie for second, both receive rank two.

[pause=0.7]

The next rank is four.

[pause=0.7]

This is useful when the numeric rank should reflect positions consumed by the tie.

[pause=1.0]

Slide 33: DENSE_RANK

DENSE_RANK also gives tied values the same rank.

[pause=0.7]

But it does not leave gaps.

[pause=0.7]

If two employees tie for second, the next distinct salary gets rank three.

[pause=0.7]

This is often useful for grouping distinct ordered levels.

[pause=1.0]

Slide 35: Deterministic ordering

Deterministic ordering matters when you use ROW_NUMBER.

[pause=0.7]

If two employees have equal salary, salary alone does not define which comes first.

[pause=0.7]

Adding employee ID creates a stable order.

[pause=0.7]

But be careful with RANK and DENSE_RANK.

[pause=0.7]

If you include employee ID inside the ranking ORDER BY, the tied salary rows are no longer peers.

[pause=0.7]

Choose the ordering based on the meaning you want.

[pause=1.0]

Slide 38: LAG

LAG is used when a question contains words such as previous, change, or time since.

[pause=0.7]

The current row remains in the result.

[pause=0.7]

LAG retrieves a value from an earlier row in the defined order.

[pause=0.7]

Partitioning prevents one patient's sequence from mixing with another patient's sequence.

[pause=0.7]

The order is part of the definition of previous.

[pause=1.0]

Slide 40: LEAD

LEAD is the forward-looking counterpart to LAG.

[pause=0.7]

It retrieves a value from the next ordered row.

[pause=0.7]

This is useful for time until next visit, next purchase, or next event.

[pause=0.7]

Again, the partition and order define the sequence.

Slide 42: Sequence order must be meaningful

Sequence analysis depends on order.

[pause=0.7]

A timestamp usually defines the main sequence.

[pause=0.7]

If two events share the same timestamp, a stable event ID can break the tie.

[pause=0.7]

Without a meaningful order, previous and next are undefined from an analytical perspective.

[pause=0.7]

Always treat the ordering clause as part of the business logic.

Slide 43: Running totals

A running total uses an ordered window frame.

[pause=0.8]

The calculation starts at the beginning of the partition and ends at the current row.

[pause=0.7]

As the current row moves forward, the frame grows.

[pause=0.7]

If we partition by department, each department gets its own running total.

Slide 47: ROWS frame

The ROWS frame counts ordered rows.

[pause=0.7]

[pause=0.7]

It does not mean two days, two hours, or two months unless every time unit has exactly one row.

[pause=0.7]

This distinction matters when the sequence has gaps.

Slide 49: LAST_VALUE pitfall

LAST_VALUE often surprises students.

[pause=0.7]

The function does not automatically look to the final row of the partition.

[pause=0.7]

It returns the last value in the current frame.

[pause=0.7]

With the default ordered frame, that frame commonly ends at the current peer group.

[pause=0.7]

If you want the final value across the entire partition, make the frame extend through unbounded following.

[pause=1.0]

Slide 51: GROUP BY vs PARTITION BY

GROUP BY and PARTITION BY both organize rows into groups, but they affect output very differently.

[pause=0.7]

GROUP BY collapses rows to the grouping grain.

[pause=0.7]

PARTITION BY defines a window context while preserving the detail rows.

[pause=0.7]

Choose based on the output grain you need, not because window functions are newer or more advanced.

[pause=1.0]

Slide 67: Ranking checkpoint

Ranking functions should be chosen from the tie rule.

[pause=0.7]

If you need exactly two rows, ROW_NUMBER is appropriate.

[pause=0.7]

If tied second-place employees should all be included, RANK fits better.

[pause=0.7]

If you want compact rank levels without gaps, use DENSE_RANK.

[pause=0.7]

The business meaning of ties determines the function.

Slide 68: Sequence checkpoint

Sequence analysis needs two things before LAG or LEAD can make sense.

[pause=0.7]
