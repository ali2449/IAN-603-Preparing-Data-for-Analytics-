Standard views

A standard view stores a query definition

Definition

The SELECT logic is stored as a database object.

Read time

Querying the view reads through its definition against current base data.

Interface

Consumers query the view by name instead of repeating the underlying SQL.

Updatable views
Some views allow writes to flow to a base table
Simple source
Typically one directly updatable base relation.
Write through view
INSERT, UPDATE, or DELETE may be translated to the base table.
Not universal
Joins, grouping, aggregates, and set operations often make a view non-updatable.

IAN 603 · Module 12 · Slide 30
Materialized views
A materialized view stores the result
Standard view
Stores a definition and reads current base data when queried.
Materialized view
Stores query results and returns the stored snapshot until refreshed.
TradeoffMaterialization exchanges freshness for precomputed results.
IAN 603 · Module 12 · Slide 31
Materialized views
Use stored results when the tradeoff is justified
Expensive summary
The underlying aggregation is costly and read frequently.
Repeated use
Many consumers need the same precomputed result.
Known refresh lag
Users can tolerate data being current only to the last refresh.
Operational plan
A refresh schedule and failure monitoring exist.

IAN 603 · Module 12 · Slide 59
Closure
The view-design habits to keep
1
Treat views as contracts
Name, columns, types, meaning, and grain matter.
2
Separate stable and temporary logic
Shared meaning belongs in views; report-specific rules can stay in CTEs.
3
Know write behavior
Simple views may be updatable; CHECK OPTION can enforce the visible filter.
4
Be precise about security
A narrow view is an interface; privileges and other controls provide authorization.
5
Materialization creates staleness
Stored results need refresh policy and freshness metadata.
6
Inspect dependencies
Shared objects should be changed with downstream consumers in mind.
