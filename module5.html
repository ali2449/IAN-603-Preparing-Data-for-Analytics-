3. Foundational Logic: The Building Blocks of Data Filtering

The bedrock of data preparation and analysis in SQL is Boolean logic. This logic is expressed through a set of foundational operators that allow for the precise filtering of data. These operators are essential for constructing a WHERE clause to isolate specific records based on a defined set of conditions.

3.1. The Core Logical Operators

The three primary Boolean operators are AND, OR, and NOT. These operators allow data professionals to combine multiple conditions to create complex and highly specific query criteria.

  • AND: This operator returns a true result only when all conditions it connects are true. It is a restrictive operator, narrowing down the result set to records that meet every single criterion.
  • OR: In contrast to AND, the OR operator returns a true result if at least one of the conditions it connects is true. It is an inclusive operator, broadening the result set to include records that satisfy any of the specified criteria.
  • NOT: This operator is used to negate a condition, returning a true result when the condition being evaluated is false. It is valuable for excluding specific data points from a result set.

These operators can be combined to create complex logical expressions. Using parentheses is a best practice to explicitly define the order of operations and prevent logical errors, especially in multi-layered queries. For example, WHERE (Condition A AND Condition B) OR (Condition C) ensures that the AND operation is performed first, treating the combined result as a single expression before the OR operation is applied.

3.2. Practical Application of Boolean Logic at a Greensboro Hospital

The public health team at the Greensboro hospital needs to identify a specific patient cohort for a new initiative targeting respiratory illnesses. The team is interested in patients who were admitted in January 2024 with a diagnosis of either 'Fever' or 'Cough' and are adults, not children.

-- Query using Boolean operators to filter data
SELECT
    P.Patient_ID,
    P.Patient_Name,
    P.Age,
    D.Diagnosis
FROM
    PATIENT_INFO AS P
INNER JOIN
    DIAGNOSTICS AS D ON P.Patient_ID = D.Patient_ID
WHERE
    (P.Age > 18) AND (D.Diagnosis LIKE '%Fever%' OR D.Diagnosis LIKE '%Cough%');

4. The NULL Conundrum: Understanding Three-Valued Logic

The presence of NULL values in a dataset is one of the most common and perplexing challenges in data preparation. A NULL value is not equivalent to a zero, an empty string, or a space; rather, it is a special marker that represents an absence of a value. It can signify that the data is either unknown or not applicable.

4.1. The Pitfall of Standard Comparisons and Three-Valued Logic

Unlike many other programming languages, SQL operates on a three-valued logic (3VL) system, where conditions can evaluate to TRUE, FALSE, or UNKNOWN. Any standard comparison involving NULL—including NULL = NULL and NULL <> NULL—returns UNKNOWN, not a boolean TRUE or FALSE. This is because it is impossible to know for certain if two unknown values are the same or different. A WHERE clause will only return rows where the condition evaluates to TRUE, so any comparison that results in an UNKNOWN state will cause the row to be excluded from the result set.

4.2. The Solution: Explicit NULL Operators

To properly handle the absence of data, SQL provides two dedicated operators: IS NULL and IS NOT NULL. These operators bypass the standard comparison logic and explicitly test for the presence or absence of a NULL value, returning a definitive TRUE or FALSE result. For example, the correct way to find patients who have no email on file is to use WHERE Email_Address IS NULL.

4.3. Expert Strategies for Handling NULLs

Beyond simple checks, modern SQL provides several powerful functions for managing NULL values:

  • COALESCE: This is an ANSI-standard function that returns the first non-null expression from a list of arguments. It is highly portable and flexible, perfect for providing a default value when data is missing.
  • NULLIF: This function returns a NULL value if its two arguments are equal; otherwise, it returns the first argument. A practical use case for NULLIF is to prevent division-by-zero errors or to clean up ambiguous values like empty strings ('').
-- Find all patients with no email address on file
SELECT Patient_ID, Patient_Name
FROM PATIENT_INFO
WHERE Email_Address IS NULL;

-- Create a preferred contact column, providing a fallback
SELECT
    Patient_ID,
    COALESCE(Email_Address, Mobile_Phone, Home_Phone, 'No Contact Provided') AS Preferred_Contact
FROM PATIENT_INFO;

5. Conditional Transformation with CASE Statements

While Boolean logic and NULL functions are used to filter and handle data, CASE statements are the primary tool for transforming data based on conditional logic. They enable data professionals to create new, derived columns that categorize, standardize, and enrich a dataset.

5.1. Dynamic Categorization and Data Enrichment

A primary application of a CASE statement is to create a new, derived column that categorizes data based on a defined set of business rules. This process transforms raw, granular data into more meaningful and aggregated categories that are more suitable for high-level reporting and analysis. For example, a hospital's billing department might need to categorize patients' final bill amounts into different tiers.

-- Categorize patient billing into tiers
SELECT
    Patient_ID,
    Bill_Amount,
    CASE
        WHEN Bill_Amount >= 10000 THEN 'High-Value'
        WHEN Bill_Amount BETWEEN 5000 AND 10000 THEN 'Standard'
        ELSE 'Low-Value'
    END AS Billing_Tier
FROM PATIENT_BILLING;

6. Case Study: Preparing Hospital Data

This section unifies the concepts of Boolean logic, NULL handling, and CASE statements in a single, practical case study using the Greensboro hospital data. The following queries demonstrate how to apply these concepts to solve real-world healthcare data problems.

Query 1: Identifying High-Risk Patients with Missing Info

Problem: The patient outreach team needs to identify patients who have a high-risk diagnosis (Diabetes or Kidney Disease) and have no email address on file. The query must use Boolean logic to combine the diagnostic conditions and IS NULL to check for the absence of an email address.

-- Query to find high-risk patients with no email contact
SELECT
    P.Patient_ID,
    P.Patient_Name,
    D.Diagnosis,
    P.Email_Address
FROM
    PATIENT_INFO AS P
INNER JOIN
    DIAGNOSTICS AS D ON P.Patient_ID = D.Patient_ID
WHERE
    (D.Diagnosis = 'Diabetes' OR D.Diagnosis = 'Kidney Disease')
    AND P.Email_Address IS NULL;

Query 2: Standardizing and Augmenting Patient Information

Problem: The billing department needs a standardized view of patient data to ensure every record has a valid contact method and a simplified billing tier. They require a new `Billing_Tier` column and a `Primary_Contact` column.

-- Query to standardize patient data for billing
SELECT
    P.Patient_ID,
    P.Patient_Name,
    B.Bill_Amount,
    COALESCE(P.Email_Address, P.Mobile_Phone, 'No Contact Info Provided') AS Primary_Contact,
    CASE
        WHEN B.Bill_Amount > 10000 THEN 'High-Value'
        WHEN B.Bill_Amount BETWEEN 5000 AND 10000 THEN 'Standard'
        ELSE 'Low-Value'
    END AS Billing_Tier
FROM
    PATIENT_INFO AS P
LEFT JOIN
    PATIENT_BILLING AS B ON P.Patient_ID = B.Patient_ID;

  1. Conceptual Question: Explain the difference between NULL and an empty string ('') in SQL, and how to handle both.
  2. SQL Coding Task: Using the ADMISSIONS table, write a query that calculates the length of stay in days for each admission. The query should use a CASE statement to categorize the stay as 'Short' (< 5 days), 'Medium' (5-10 days), or 'Long' (> 10 days). You must also exclude any admissions without a discharge date.
  3. Application Scenario: A hospital administrator wants a report on admissions from the past 30 days that have a 'Pneumonia' or 'Flu' diagnosis. The report should show the patient's name and age, and categorize the diagnosis into a 'High-Risk Respiratory' or 'Other' group.

Solution for Question 1

A NULL is a marker for missing or unknown data, while an empty string ('') is an actual value that represents a zero-length string. They are not the same. You test for NULL using IS NULL, and for an empty string using a standard equality check like = ''. A common practice is to use NULLIF to convert empty strings to NULL values, which can then be handled with other NULL-specific functions like COALESCE.

Solution for Question 2

SELECT
    Admission_ID,
    JULIANDAY(Discharge_Date) - JULIANDAY(Admission_Date) AS Length_of_Stay,
    CASE
        WHEN JULIANDAY(Discharge_Date) - JULIANDAY(Admission_Date) < 5 THEN 'Short Stay'
        WHEN JULIANDAY(Discharge_Date) - JULIANDAY(Admission_Date) BETWEEN 5 AND 10 THEN 'Medium Stay'
        ELSE 'Long Stay'
    END AS Stay_Category
FROM ADMISSIONS
WHERE Discharge_Date IS NOT NULL;
