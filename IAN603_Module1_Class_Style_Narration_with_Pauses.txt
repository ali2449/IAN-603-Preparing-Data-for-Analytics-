Slide 5: Four different questions

The phrase data type is often used too broadly.

[pause=0.7]

In this course, we separate four layers.

[pause=0.7]

Data organization describes the form of the dataset. Measurement scale describes the meaning of one variable. Numeric behavior asks whether a quantitative concept comes from counting or measuring. Technical representation describes how software stores the value.

[pause=0.7]

A single variable can have an answer at several layers, and those answers are not interchangeable.

[pause=1.0]

Slide 7: Data organization overview

The first major question is how the dataset is organized.

[pause=0.7]

Structured data follows a predefined schema. Semi-structured data has named fields but allows flexibility and nesting. Unstructured data does not naturally arrive as rows and columns.

[pause=0.7]

These categories describe organization.

[pause=0.7]

A structured table can still have missing values, duplicate records, or poorly defined variables. Organization and quality are separate issues.

[pause=1.0]

Slide 8: Structured data

Structured data follows a stable arrangement.

[pause=0.7]

Relational databases are a classic example because each row follows a known set of columns and types.

[pause=0.8]

CSV and Parquet files can also contain structured data.

[pause=0.7]

The benefit is predictability. We can validate and query fields consistently.

[pause=0.7]

But structured does not mean correct. A structured table can still contain duplicates, missing values, inconsistent categories, or impossible measurements.

[pause=1.0]

But the columns do not all have the same analytical meaning.

[pause=0.7]

Patient ID and ZIP code are labels. Date of birth is temporal. Sex and blood type are categorical.

[pause=0.8]

This is a useful example of the distinction between dataset organization and variable meaning.

[pause=0.8]

The dataset is structured, but each variable still needs its own classification.

Slide 10: Semi-structured data

Semi-structured data has some organization without requiring every record to look exactly the same.

[pause=0.7]

JSON is a common example.

[pause=0.8]

Fields have names, but values can be nested, and different records may contain different keys.

[pause=0.7]

That flexibility is useful for APIs, devices, logs, and fast-changing applications.

[pause=0.7]

The tradeoff is that analysts often need to flatten records, handle optional fields, and manage schema changes before analysis.

[pause=1.0]

Slide 11: Nested JSON example

But it is not a flat table. Heart rate is nested inside metrics, and latitude and longitude are nested inside location.

[pause=0.7]

A second record could add oxygen saturation or omit sleep hours.

[pause=0.7]

Before analysis, we often flatten the JSON into columns.

[pause=0.7]

But flattening is only a structural step. We still need to understand units, missingness, and the analytical meaning of the extracted fields.

Slide 12: Unstructured data

Unstructured data does not naturally arrive as a table.

[pause=0.7]

A clinical note contains useful information, but the meaning is embedded in text. An image contains visual information. Audio contains signals over time.

[pause=0.7]

To analyze these sources, we usually need an extraction step such as NLP, computer vision, OCR, or speech processing.

[pause=0.7]

After extraction, some information may become structured features that can be analyzed alongside relational data.

Slide 15: Data quality overview

Now we move from organization to quality.

[pause=0.7]

A dataset can be perfectly structured and still be unsuitable for analysis.

[pause=0.7]

Quality is contextual. Data that is acceptable for a monthly report may be too stale for a real-time dashboard.

[pause=0.7]

Quality is also evidence-based. An unusual value should be investigated before we automatically delete or replace it.

[pause=0.7]

We will use six dimensions and a five-step workflow to reason about quality.

[pause=1.0]

Slide 16: Six quality dimensions

These six dimensions give us a practical checklist.

[pause=0.7]

Accuracy asks whether a value reflects reality. Completeness asks whether required information is present. Consistency asks whether the same concept is represented compatibly.

[pause=0.7]

Timeliness asks whether the data is current enough. Uniqueness asks whether entities appear the intended number of times. Validity checks whether values follow documented rules.

[pause=0.7]

The dimensions can overlap, so treat them as a way to organize investigation rather than as perfectly separate boxes.

[pause=1.0]

Slide 17: Accuracy vs validity

Validity and accuracy are related but different.

[pause=0.7]

Validity asks whether a value fits a documented rule.

[pause=0.7]

Accuracy asks whether the value reflects reality.

[pause=0.7]

A temperature can fall inside an allowed range and still be inaccurate because of a sensor problem or data-entry error.

[pause=0.8]

Validity is often easier to automate. Accuracy may require comparison with the source system, another measurement, or domain knowledge.

[pause=0.7]

This distinction prevents us from assuming that passing a validation rule proves the value is true.

[pause=1.0]

Slide 18: Completeness vs uniqueness

Completeness and uniqueness are different problems.

[pause=0.7]

Completeness asks whether needed values are present. The seriousness depends on the field and the use case. Missing email may be acceptable while missing patient ID may be critical.

[pause=0.8]

Uniqueness asks whether one real-world entity appears more than intended.

[pause=0.7]

Exact duplicate rows are easy to detect. Duplicate entities under different identifiers are harder and may require entity-resolution methods.

[pause=0.7]

Always distinguish missing information from repeated identity.

[pause=1.0]

Slide 19: Consistency vs timeliness

Consistency asks whether the same concept is represented the same way.

[pause=0.7]

Mixed date formats, category labels, and units can create serious interpretation problems.

[pause=0.8]

Timeliness is different. It asks whether the data is current enough for the decision.

[pause=0.7]

A fifteen-minute delay may be excellent for a monthly reporting process but unacceptable for an emergency monitoring system.

[pause=0.7]

Both dimensions require documentation: shared definitions for consistency and timestamps or refresh expectations for timeliness.

[pause=1.0]

Slide 20: Quality workflow

A practical quality workflow has five steps.

[pause=0.7]

First, profile the data. Second, detect potential issues. Third, investigate the source and context.

[pause=0.7]

Only then decide whether to correct, retain, exclude, impute, or flag the value.

[pause=0.7]

Finally, document what happened.

[pause=0.7]

This sequence creates an audit trail and reduces the risk of silently changing legitimate unusual values.

[pause=1.0]

Slide 21: Heart-rate quality scenario

The heart-rate scenario shows why quality work requires judgment.

[pause=0.7]

Minus one is clearly incompatible with a normal heart-rate measurement. A blank value is a completeness problem.

[pause=0.7]

Two hundred is unusual, but it may be physiologically possible in some circumstances.

[pause=0.7]

That means we investigate rather than automatically delete it.

[pause=0.7]

Quality rules help us identify records that deserve attention. They do not replace domain reasoning.

[pause=1.0]

Slide 22: Quality actions

After identifying a quality problem, we still need a response.

[pause=0.7]

Sometimes we can correct a value. Sometimes we retain it. Sometimes we exclude it from one analysis without deleting it from the source. Sometimes we impute missing information.

[pause=0.7]

Often, a quality flag is the most transparent choice when uncertainty remains.

[pause=0.7]

The objective is not to make the dataset look perfect. It is to make limitations explicit and manageable.

[pause=1.0]

Slide 23: Measurement scale overview

Now we move from quality to variable meaning.

[pause=0.7]

Measurement scale tells us which comparisons and arithmetic operations are defensible.

[pause=0.7]

Nominal and ordinal are categorical scales. Interval and ratio are numeric scales.

[pause=0.7]

The key questions are whether order exists, whether differences have a consistent meaning, and whether zero represents the absence of the measured quantity.

[pause=1.0]

Slide 24: Categorical vs numeric

The broadest split is categorical versus numeric.

[pause=0.7]

Categorical variables represent labels or ordered levels. Nominal and ordinal belong here.

[pause=0.8]

Numeric variables represent quantities. Interval and ratio belong here.

[pause=0.7]

Do not decide by looking only at the characters in the column.

[pause=0.7]

A ZIP code contains digits but is categorical. A satisfaction score uses numbers but usually represents ordered categories.

[pause=1.0]

Slide 25: Measurement decision tree

This decision tree provides a simple reasoning process.

[pause=0.7]

First, ask whether the values are labels or quantities.

[pause=0.8]

If they are labels, ask whether a meaningful order exists. If they are quantities, ask whether the scale has a true zero.

[pause=0.8]

This framework works well for many common variables, but domain context still matters.

[pause=0.7]

When unsure, explain which comparisons or arithmetic statements would make real-world sense.

[pause=1.0]

Slide 26: Nominal scale

Nominal variables distinguish categories without placing them in a meaningful order.

[pause=0.7]

Blood types are different, but one blood type is not greater than another.

[pause=0.7]

ZIP codes and patient IDs are common traps because they may contain digits.

[pause=0.7]

Counts and proportions are natural summaries, and bar charts are usually a good starting visualization.

[pause=0.7]

The important rule is not to invent numerical meaning for a label.

[pause=1.0]

Slide 27: Nominal visualization

A bar chart is a natural display for a nominal variable.

[pause=0.7]

The bar lengths show counts, which are quantitative.

[pause=0.7]

The category labels themselves are not treated as measurements.

[pause=0.8]

We can reorder the categories by frequency or by a conventional order without implying that O minus A has any numerical meaning.

[pause=0.7]

This is a good example of matching a visualization to the measurement structure.

[pause=1.0]

Slide 28: Ordinal scale

Ordinal variables have a meaningful order.

[pause=0.7]

Emergent is more severe than urgent, and urgent is more severe than non-urgent.

[pause=0.7]

But the distance between those levels is not necessarily equal.

[pause=0.7]

That means numeric codes can preserve rank while still requiring caution.

[pause=0.7]

Medians, percentiles, and ordered displays often respect the structure better than treating the values as ordinary continuous numbers.

[pause=1.0]

Slide 29: Likert caution

Likert-style responses illustrate ordinal data well.

[pause=0.7]

A five is higher than a four, but the psychological distance from one to two may not equal the distance from four to five.

[pause=0.7]

Means are commonly reported in practice, particularly for composite scales.

[pause=0.7]

But for a single coarse item, medians, distributions, and rank-based summaries may better respect the measurement assumptions.

[pause=0.7]

The important point is to recognize the assumption rather than use the mean automatically.

[pause=1.0]

Slide 30: Interval scale

Interval scales support meaningful differences.

[pause=0.7]

Celsius temperature is the classic example.

[pause=0.8]

A difference of five degrees has the same interpretation anywhere on the scale.

[pause=0.7]

But zero Celsius is not the absence of temperature.

[pause=0.7]

Because the zero point is arbitrary, ratio statements such as twenty degrees being twice ten degrees are not meaningful.

[pause=1.0]

Slide 31: Ratio scale

Ratio scales have equal differences and a meaningful zero.

[pause=0.7]

Zero visits means no visits occurred. Zero elapsed seconds means no time elapsed.

[pause=0.7]

Because the zero point represents absence, ratio statements can be meaningful.

[pause=0.7]

Four visits can be twice two visits.

[pause=0.7]

Ratio variables support a wide range of arithmetic, although distribution, units, and context still affect which summaries are useful.

[pause=1.0]

Slide 32: Interval vs ratio

Interval and ratio variables can look similar because both are numeric and support meaningful differences.

[pause=0.7]

The major distinction is the zero point.

[pause=0.7]

Celsius zero is a reference point, not the absence of temperature.

[pause=0.7]

Zero visits means no visits occurred.

[pause=0.7]

That difference determines whether ratio statements are meaningful.

[pause=0.7]

When classifying a numeric variable, ask what zero means in the real-world measurement process.

[pause=1.0]

Slide 33: Discrete vs continuous

Numeric variables can also be classified by how the values are generated.

[pause=0.7]

Discrete variables usually come from counting events or units.

[pause=0.7]

Continuous variables come from measurement and conceptually can take values along a range.

[pause=0.7]

Do not confuse the stored precision with the concept.

[pause=0.7]

A device may report a continuous physiological measurement as a whole number because that is how the instrument records it.

[pause=1.0]

Slide 34: When integer storage misleads

This slide shows four columns that could all be stored as integers.

[pause=0.7]

Heart rate is a measurement recorded to whole units. Emergency visits is a count. Patient ID is a label. Satisfaction is ordinal.

[pause=0.8]

The same technical dtype supports four different analytical meanings.

[pause=0.7]

This is why the correct question is not, what dtype does pandas show?

[pause=0.7]

The correct question is, how was this value generated and what comparisons make sense?

Slide 35: Common classification traps

These are common classification traps.

[pause=0.7]

The visual appearance of a value can tempt us to classify too quickly.

[pause=0.7]

ZIP codes and patient IDs are labels. Satisfaction is ordered but not necessarily equally spaced. Heart rate may be stored as an integer while representing a measurement. ER visits is a count. Celsius temperature is interval rather than ratio.

[pause=0.8]

When in doubt, describe the variable in a sentence and ask what operations make real-world sense.

Slide 36: From type to decision

Classification should lead to an analytical decision.

[pause=0.7]

Once you understand the variable, choose summaries that respect the scale, visualizations that show the intended comparison, and encodings that do not introduce false structure.

[pause=0.7]

Then validate the transformed result.

[pause=0.7]

This is not a rigid cookbook.

[pause=0.7]

Distribution, study design, and analytical goals still matter, but measurement meaning gives us a defensible starting point.

[pause=1.0]

Slide 37: Summary choices

Choosing a summary is a conceptual decision.

[pause=0.7]

Counts and proportions fit nominal categories naturally.

[pause=0.7]

Ordinal variables often support medians and percentiles.

[pause=0.7]

Numeric variables may use means and standard deviations when the mean is meaningful and the distribution is appropriate.

[pause=0.7]

Skewed numeric data often benefits from median and interquartile range.

[pause=0.7]

Do not apply the same summary mechanically to every column in a dataframe.

[pause=1.0]

Slide 38: Visualization choices

Visualization should respect the variable structure.

[pause=0.7]

Bar charts work well for nominal categories. Ordered bars preserve the order of ordinal categories.

[pause=0.7]

Histograms show the distribution of continuous numeric variables. Scatterplots show relationships between two numeric variables.

[pause=0.7]

A chart should make the intended comparison easier without adding structure that the data does not contain.

[pause=0.7]

For example, connecting unordered categories with a line can accidentally imply continuity.

[pause=1.0]

Slide 39: Encoding choices overview

Encoding changes how software represents a variable.

[pause=0.7]

It does not change the underlying meaning.

[pause=0.7]

Nominal variables often use one-hot indicators. Ordinal variables may use ordered categorical dtypes or explicit ordinal codes. Numeric variables can remain numeric and may be scaled for methods that need comparable feature scales.

[pause=0.7]

Counts should remain conceptually counts even if a model later transforms them.

[pause=0.7]

The representation should support, not redefine, the concept.

[pause=1.0]

Slide 40: Membership tier example

Membership tier is an ordered category, but it can be represented in more than one way.

[pause=0.7]

An ordinal code preserves the rank from Bronze through Platinum.

[pause=0.7]

A one-hot representation avoids expressing the category as a single numeric distance.

[pause=0.7]

[pause=0.7]

Slide 41: One-hot encoding

One-hot encoding creates separate indicator columns.

[pause=0.7]

With Bronze as the reference category, the generated columns represent Silver, Gold, and Platinum. Bronze is represented by all zeros.

[pause=0.7]

This is useful when we do not want a model to treat categories as points on one numeric line.

[pause=0.7]

The tradeoff is dimensionality. Variables with many categories can create many columns.

[pause=1.0]

Slide 42: Ordinal encoding

Ordinal encoding maps ordered categories to ordered numbers.

[pause=0.7]

The representation is compact and preserves rank.

[pause=0.7]

But some analytical methods may interpret the gaps between codes as equal.

[pause=0.7]

That is an additional assumption, not something guaranteed by the original category labels.

[pause=0.8]

Whenever you use ordinal codes, document the intended order and understand how the downstream model uses numeric distance.

Slide 43: Data leakage

One important preprocessing idea is data leakage.

[pause=0.7]

If we fit a scaler or learned encoder using the entire dataset before evaluation, information from validation or test data can influence the transformation.

[pause=0.7]

A safer workflow fits learned preprocessing on the training data and applies the fitted transformation to validation or test data.

[pause=0.7]

Module 1 is not a machine-learning module, but this habit is worth establishing now because preprocessing can affect the honesty of later evaluation.
