About the course

From raw data to analysis-ready data

IAN 603 focuses on the practical work that happens before analysis and modeling: understanding data structure, querying relational data, combining sources, cleaning values, reshaping datasets, building reusable analytical SQL, and scaling familiar ideas to Spark.

1

Understand the data

Identify row grain, variable meaning, data types, quality issues, keys, and relationships before writing transformations.

2

Prepare with SQL

Filter, aggregate, join, clean, standardize, validate, reshape, and create analysis-ready outputs with PostgreSQL.

3

Reason about correctness

Protect grain, NULL meaning, cardinality, duplicate logic, temporal meaning, and the interpretation of analytical results.

4

Build reusable workflows

Use advanced SQL, views, modular query design, and distributed Spark concepts to move beyond one-off queries.

How to use the narrated slides

Use each module as a guided lesson and a practice environment

You do not need to rush through a module in one sitting. Pause the narration, run examples, inspect results, and return to difficult slides as needed.

1

Open a module

Choose a module from the directory below. Use the module sequence if you are learning the material for the first time.

2

Start narration

Select Start Narration. The audio explains the slide in more detail than the visible text, including code reasoning and what to observe.

3

Use CC or Transcript

Turn closed captions on or off from the bottom controls. Use Transcript when you want to read the complete narration at your own pace.

4

Run the examples

Where the module includes a browser database, edit SQL and choose Run. Read the result table before moving to the next slide.

5

Practice outside the slides

Use Copy to move SQL into pgAdmin when you want a full PostgreSQL environment. Spark examples should be practiced in an actual Spark environment such as Fabric, Databricks, or Apache Spark.

6

Complete the checks

Use guided practice, checkpoints, and project slides to make sure you can explain the result, not only run the code.

Useful controls

Inside most modules

  • Previous / Next and arrow keys move between slides.
  • CC On / Off controls bottom subtitles.
  • Transcript opens the current slide narration text.
  • Playback speed lets you slow down or speed up narration.
  • Seek bar lets you revisit part of the current audio.
  • Dark mode and Full screen are available in the top controls.
  • The narration does not automatically move to the next slide. You decide when to continue.
Browser practice note: PostgreSQL modules may use a browser-based teaching database. This is designed for practice. You can copy the same SQL to pgAdmin for a full local PostgreSQL workflow.
Recommended study workflow

Do more than watch the presentation

The most effective pattern is to alternate explanation with practice. Data preparation is a reasoning skill, so try to predict a result before you run the query.

Watch & listen

Use narration to understand why a technique is used, what row grain it creates, and which mistakes it is designed to avoid.

Pause & predict

Before running SQL, predict the number of rows, columns, NULL behavior, grouping level, or expected category result.

Run & inspect

Read the output carefully. Do not treat a successful query as proof that the logic is correct.

Modify

Change a condition, category, date range, join type, or grouping level and observe how the result changes.

Explain

Try to explain the query in plain language. If you cannot explain what one row represents, review the grain before continuing.

Apply

Use the same pattern on an assignment or a new dataset rather than copying the teaching example unchanged.

Course use guide

Common questions

Do I need PostgreSQL installed to use the slides?

No for many teaching examples. Several modules provide a browser-based PostgreSQL environment for practice. For assignments, larger projects, or a full database workflow, use pgAdmin/PostgreSQL when instructed.

Should I watch all narration without stopping?

No. The narration is designed to guide you through the lesson, but you should pause frequently for code, checkpoints, tables, and comparisons. The slides never force you to move forward when audio ends.

What is the difference between captions and transcript?

Closed captions display the current timed narration at the bottom. The transcript gives you the full narration text for the current slide so you can read or review it independently of audio playback.

Why do the modules repeatedly discuss row grain?

Many data-preparation mistakes come from losing track of what one row represents. Grain affects joins, aggregation, reshaping, window functions, data quality checks, and reusable views, so it is intentionally reinforced throughout the course.

Can I jump directly to an advanced module?

You can, but Modules 11 through 13 build on concepts such as joins, aggregation, NULL logic, temporal preparation, and grain. If an advanced example feels difficult, use the learning path above to identify the prerequisite module.

Where is my completion progress saved?

The checkboxes on this page use your browser's local storage only. They are a personal study aid and are not automatically submitted to a learning-management system or sent to a server.
