SELECT

A query can be read as a sentence

SELECT columns→FROM table→WHERE condition→ORDER BY→LIMIT

What appears?

SELECT chooses the columns or expressions returned in the result.

Where does it come from?

FROM identifies the source table. Later modules expand this to joins.

Good default: list the columns you actually need instead of starting every query with SELECT *.

A failed DELETE can be a good result

Patient MRN1004 has an admission. The foreign key uses ON DELETE RESTRICT, so PostgreSQL blocks an orphan record.

RunExpected foreign-key errorThe database protects related data

Interpret errors: constraint errors are not just “bad SQL.” They can prove that the schema is enforcing an important rule.
Transactions

Transaction ideas

ACID in one view

Atomicity

Related changes succeed together or are undone together.

Consistency

Rules and constraints still hold when the transaction finishes.

Isolation

Concurrent work is controlled so intermediate states do not interfere incorrectly.

Durability

Committed changes persist in a durable server database.

Common mistakes

Small habits prevent large problems

MistakeWhy it causes troubleBetter practice
column = NULLNULL does not behave like an ordinary value.column IS NULL
Mixed AND/OR without parenthesesOperator precedence may select unexpected rows.Use parentheses to show intended groups.
LIMIT without a sortThe returned subset is not a dependable “top” set.Use deterministic ORDER BY.
UPDATE by nameNames may repeat or change.Use a primary or unique key.
DELETE without previewYou may remove the wrong rows.Run the matching SELECT first.

Self-check

Can you explain these without running code?

1. Why is an explicit column list usually better than SELECT *?
2. What is wrong with WHERE discharge_date = NULL?
3. Why should LIMIT usually be paired with ORDER BY?
4. What should you run before a new UPDATE or DELETE?
5. What is the difference between COMMIT and ROLLBACK?
Show sample answers
  1. It makes the output clear and avoids retrieving unused columns.
  2. Use IS NULL because NULL is not tested with ordinary equality.
  3. Without ordering, the limited rows do not reliably represent latest, oldest, or top.
  4. Run a SELECT with the same predicate and inspect the target rows.
  5. COMMIT keeps transaction changes; ROLLBACK discards them.

Summary

Retrieve

Filter

WHERE, BETWEEN, IN, ILIKE, and NULL predicates choose rows.

Change

Protect

Keys, constraints, transactions, and RETURNING make changes safer.
