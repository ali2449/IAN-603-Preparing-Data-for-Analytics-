Remember: the join type controls preservation; the ON expression controls matching.
INNER

Matched combinations only.

LEFT

Every left row plus matches.

RIGHT

Every right row plus matches.

FULL OUTER

All rows from both sides.

Prediction question: where will NULL values appear when an outer join keeps an unmatched row?

ON

Controls which right-side rows are allowed to match.

WHERE

Filters the result after the join has created matched and unmatched rows.

Outer-join warning: filtering an optional-side column in WHERE can remove the NULL-extended rows you wanted to preserve.

Always estimate first. CROSS JOIN is powerful when the combinations are intentional.
One-to-one

At most one match per key.

One-to-many

A parent row may repeat for several child rows.

Many-to-many effect

Multiple child tables can multiply combinations.

Before joining: identify zero, one, or many possible matches on each side.

Risk

COUNT(*) counts every joined row combination.

Safer choices

Use event keys with COUNT(DISTINCT ...), or pre-aggregate each child to the target grain.

Do not fix blindly with DISTINCT. First decide what event you are actually counting.
