Module 1: Introduction to Data in Informatics

Data types (structured, semi-structured, unstructured) and measurement scales (nominal, ordinal, interval, ratio), including discrete vs. continuous, encoding, visualization, and typical modeling paths.

Updated: August 26, 2025

Learning Objectives

  • Classify data as structured, semi-structured, or unstructured and state common sources/tools for each.
  • Explain the four measurement scales (nominal, ordinal, interval, ratio) and choose appropriate stats and visuals.
  • Distinguish discrete vs continuous numerics and pick sensible models and encodings.
  • Apply pandas/scikit-learn to set dtypes, encode categorical variables, and scale numeric features.
  • Map analytics data types to SQL column types and write constraints for validity.

Why Data Types & Scales Matter

Choice of data type and measurement scale affects: (1) which statistics are valid, (2) how you encode features, (3) which visualizations make sense, and (4) what models are appropriate. For example, a five-point satisfaction item is ordinal (order but not equal gaps), so medians/IQRs or rank tests are safer than means when distributions are skewed; if you still treat it as interval, document why and check robustness with non-parametrics. (See references at the end.)

Context: Modern datasets vary in Volume, Velocity, Variety (the “3Vs” popularized by Doug Laney). Variety is exactly the mix of structured, semi-structured, and unstructured data you’ll wrangle in this course.

The Data Landscape (with Examples)

Structured Data

  • What it is: Predefined schema (tables, rows, columns). Easy to query with SQL.
  • Where it lives: PostgreSQL/MySQL/SQL Server; data warehouses; CSV/Parquet exports.
  • Examples:
    • Healthcare EHR tables: patients, encounters, labs.
    • Retail: orders(order_id, customer_id, order_date, total_amount).
    • Finance: transactions with decimals for currency.
  • Prep focus: Types, ranges, NOT NULLs, referential integrity, deduping.

Semi-Structured Data

  • What it is: Flexible, self-describing formats (JSON, XML). Fields may be optional or nested.
  • Where it lives: API payloads, logs, IoT streams, document stores (MongoDB), data lakes.
  • Prep focus: Parsing, schema inference, JSON flattening, harmonizing keys/units.
{
  "patient_id": "P1001",
  "timestamp": "2025-07-28T10:30:00Z",
  "metrics": {"hr": 72, "steps": 500, "sleep_hours": 7.5},
  "location": {"lat": 36.07, "lon": -79.79}
}

Another record might add "spo2": 0.97 or omit sleep_hours. Expect variability.

Unstructured Data

  • What it is: No predefined schema (free text, images, audio, video).
  • Where it lives: Clinical notes, PDFs, DICOM images, call recordings, social posts.
  • Prep focus: NLP (tokenization/NER), computer vision, ASR; convert to structured features.
NIST terminology: Structured data has a predefined model; unstructured lacks one; semi-structured sits between. (See References.)

Measurement Scales (Nominal, Ordinal, Interval, Ratio)

These scales (originating with S. S. Stevens) determine what math is valid and how you should plot/analyze.

ScaleOrdered?Equal Differences?True Zero? Typical ExamplesStats You Can TrustGood Visuals
Nominal (categorical) NoNoNo Color, blood type, device type, ZIP Counts, mode, proportions; χ² tests Bar chart, mosaic
Ordinal (categorical) YesNot guaranteedNo Education level; satisfaction 1–5 Median/IQR, percentiles; rank tests Ordered bars; median/IQR plots
Interval (numeric) YesYesNo Temperature (°C/°F), calendar year Mean/SD, correlation; ratios invalid Histogram, line charts
Ratio (numeric) YesYesYes Age, weight, income, distance, time All arithmetic incl. ratios Histogram, box/violin, scatter
Likert caution: Single 1–5 items are ordinal; means are commonly reported but medians/IQRs and non-parametrics are safer when distributions are skewed or scales are coarse. If you aggregate many items into a validated composite, treating as approximately interval is more defensible—still justify and check robustness.

Numeric Types: Discrete vs. Continuous

Discrete (Counts)
  • Arises from counting (0,1,2,…).
  • Examples: ER visits, purchases, readmissions, defects.
  • Usually ratio scale (0 means none; “twice as many” makes sense).

Modeling: Poisson or Negative Binomial; zero-inflated variants when many zeros; consider exposure offsets (e.g., time at risk).

Continuous (Measurements)
  • Arises from measurement (precision-limited).
  • Examples: height, lab values, session duration, income.
  • Interval or ratio depending on whether zero is meaningful.

Modeling: Linear/GAM; use transforms (log) for heavy tails; robust scalers for outliers.

Edge case: Integer-stored vitals (e.g., heart rate) measure a continuous phenomenon—treat conceptually, not by storage type.

Encoding, Visualization, & Common Pitfalls

Nominal
  • Encoding: One-hot (dummy). Group very rare levels into “Other”.
  • Viz: Bars/mosaic; order by frequency; show percentages.

High cardinality? Consider target/mean encoding with nested CV to avoid leakage.

Ordinal
  • Encoding: Ordinal codes with documented order (or one-hot if order uncertain).
  • Viz: Ordered bars; medians with IQRs.

Don’t imply equal gaps unless justified (e.g., validated composite score).

Interval / Ratio
  • Keep numeric; standardize for distance-based models.
  • Log-scale heavy-tailed variables (time, revenue).

For currency, use exact DECIMAL/NUMERIC in SQL, not float.

Python/Pandas: Practical Snippets

Detect dtypes, set nominal/ordinal, one-hot vs ordinal encoding, and scaling:

import pandas as pd
from pandas.api.types import CategoricalDtype
from sklearn.preprocessing import OrdinalEncoder, OneHotEncoder, StandardScaler

df = pd.DataFrame({
    "gender": ["F","M","F","F","M"],            # nominal
    "edu_level": ["HS","BS","MS","PhD","BS"],   # ordinal
    "age": [19, 33, 28, 41, 37],                # ratio (continuous)
    "temp_c": [22.0, 21.5, 23.1, 20.0, 19.8],   # interval
    "er_visits": [0, 3, 2, 5, 1],               # ratio (count)
    "member_tier": ["Bronze","Silver","Gold","Platinum","Silver"]  # ordinal
})

# Nominal to pandas 'category'
df["gender"] = df["gender"].astype("category")

# Ordinal with explicit order (pandas)
edu_order = CategoricalDtype(categories=["HS","BS","MS","PhD"], ordered=True)
df["edu_level"] = df["edu_level"].astype(edu_order)
df["edu_code"] = df["edu_level"].cat.codes  # HS=0 ... PhD=3

# OrdinalEncoder (sklearn) with specified order
enc = OrdinalEncoder(categories=[["Bronze","Silver","Gold","Platinum"]])
df["tier_code"] = enc.fit_transform(df[["member_tier"]]).astype(int)

# One-hot for nominal
ohe = OneHotEncoder(drop="first", sparse_output=False)  # avoids dummy trap
gender_oh = ohe.fit_transform(df[["gender"]])
ohe_cols = [f"gender_{c}" for c in ohe.categories_[0][1:]]
df[ohe_cols] = gender_oh

# Scale numeric features (fit on train only in practice)
scaler = StandardScaler()
num_cols = ["age","temp_c","er_visits"]
df[[c + "_z" for c in num_cols]] = scaler.fit_transform(df[num_cols])
print(df.dtypes)
print(df.head())
Notes: Use dtype='category' or CategoricalDtype for pandas categoricals. In scikit-learn, OrdinalEncoder enforces a single integer column per feature; StandardScaler standardizes numeric features (mean 0, variance 1). See References for docs.

SQL Mapping & Constraints

Analytics TypeTypical SQL TypePractical Notes
NominalVARCHAR/TEXTConstrain with CHECK; index selective columns.
OrdinalSMALLINT or VARCHAR+CHECKDocument mapping table (code→label, order).
IntervalINTEGER/FLOAT; DATE/TIMESTAMPYears as INT; time types retain calendar meaning.
Ratio (continuous)DECIMAL/NUMERICUse for currency (exact arithmetic), avoid FLOAT rounding.
Ratio (count)INTEGER/BIGINTEnforce non-negativity: CHECK(value >= 0).
 
-- Example DDL
CREATE TABLE orders (
  order_id BIGSERIAL PRIMARY KEY,
  customer_id BIGINT NOT NULL,
  order_date DATE NOT NULL,
  -- use exact DECIMAL/NUMERIC for money
  total_amount NUMERIC(12,2) NOT NULL CHECK (total_amount >= 0),
  currency CHAR(3) NOT NULL CHECK (currency IN ('USD','EUR','GBP'))
);

-- Ordinal mapping table
CREATE TABLE membership_tier (
  tier_code SMALLINT PRIMARY KEY,
  tier_label VARCHAR(20) UNIQUE NOT NULL,
  tier_rank SMALLINT NOT NULL CHECK (tier_rank BETWEEN 1 AND 4)
);

Mini Case Studies

Healthcare
  • Outcome: Length of stay (days) → ratio, discrete count of days (conceptually continuous time).
  • Predictors: Diagnosis code (nominal), pain score 0–10 (ordinal), temperature °C (interval), age (ratio), comorbidity count (ratio-discrete).
  • Modeling path: For count outcomes (readmissions): Poisson/NB; check over-dispersion; zero-inflation if many zeros.
  • Viz: Box/violin for length of stay; ordered bars for pain score distribution.
E-commerce
  • Outcome: Purchases in 30 days → ratio (count).
  • Predictors: Device (nominal), membership tier (ordinal), session duration (ratio), weekday (nominal cyclical).
  • Encoding: One-hot device/weekday; ordinal tier; log duration if heavy-tailed.
  • SQL tip: Store currency in NUMERIC with ISO-4217 currency code.
