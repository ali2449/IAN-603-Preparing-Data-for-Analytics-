Learning Objectives

By the end of this module, you will be able to:

  1. Distinguish data organization - structured, semi-structured, and unstructured - from variable measurement type.
  2. Evaluate a dataset using accuracy, completeness, consistency, timeliness, uniqueness, and validity.
  3. Classify variables as nominal, ordinal, interval, or ratio and distinguish discrete counts from continuous measurements.
  4. Select defensible summaries, visualizations, and encodings based on variable meaning.
  5. Use pandas and scikit-learn to assign categorical types, encode variables, normalize JSON, and scale selected numeric features.
  6. Explain how analytical meaning differs from a pandas dtype or SQL storage type.

One Phrase, Four Different Questions

The phrase data type is often used loosely. In this module, keep these four layers separate.

Layer 1

Data Organization

Question: How is the dataset organized?

Structured, semi-structured, or unstructured

Layer 2

Measurement Scale

Question: What do a variable's values mean?

Nominal, ordinal, interval, or ratio

Layer 3

Numeric Behavior

Question: Is the numeric value counted or measured?

Discrete or continuous

Layer 4

Technical Representation

Question: How is the value stored?

pandas dtype, file format, or SQL column type

Core distinction: A variable's storage type does not determine its analytical meaning. A ZIP code may be stored as an integer but is still a nominal category. A satisfaction score may be stored as an integer but is still ordinal.

1. How Data Is Organized

Classify the form of the dataset before classifying individual variables inside it.

Structured

Predefined Schema

Data follows a stable arrangement of rows, columns, and defined fields.

Common locations:

PostgreSQL, MySQL, SQL Server, data warehouses, CSV, and Parquet files.

Running-case example:

patients, encounters, and labs tables.

Semi-Structured

Flexible, Self-Describing Fields

Records contain labels or tags, but fields may be nested, optional, or inconsistent across records.

Common locations:

API payloads, logs, IoT streams, document stores, and data lakes.

Running-case example:

A wearable-device JSON payload with nested metrics.

Unstructured

No Fixed Tabular Schema

The content does not naturally arrive as rows and columns.

Common locations:

Clinical notes, PDFs, DICOM images, audio, video, and social posts.

Running-case example:

A free-text discharge note or diagnostic image.

A second record might add spo2 or omit sleep_hours. That flexibility is useful, but it creates a schema-management task.

The 3Vs in context: Modern data is often described by Volume, Velocity, and Variety. Variety is the mixture of structured, semi-structured, and unstructured data that informatics professionals must integrate.
Checkpoint: "Structured" describes the organization of a dataset. It does not mean that every column is numeric, clean, or ready for analysis.

2. Is the Data Trustworthy?

Before selecting statistics or models, assess whether the data is fit for the intended purpose.

Six data quality dimensions
Dimension Question Example Issue Possible Response
Accuracy Does the value reflect reality? Patient weight recorded as 500 kg. Range checks, source verification, and review of data-entry rules.
Completeness Are required values present? blood_type is missing for 20% of records. Required-field rules, missingness analysis, imputation, or explicit flags.
Consistency Is the same information represented the same way? Dates appear as 1985-05-15 and 05/15/85. Standardized formats, shared definitions, and referential integrity.
Timeliness Is the data current enough for the task? Last month's census powers a real-time dashboard. Refresh schedules, timestamps, and data-latency documentation.
Uniqueness Does each real-world entity appear as intended? The same patient appears twice under different IDs. Deduplication, unique constraints, and entity resolution.
Validity Does the value conform to an appropriate documented rule? encounter_status contains "finished" although the approved values are "scheduled," "completed," and "cancelled." Domain lists, CHECK constraints, regular expressions, and validation tests.

These dimensions overlap. A blank required field is incomplete and may also be invalid. The acceptable quality threshold depends on the decision the data will support.

A Practical Quality Workflow

1. Profile
Summarize fields, ranges, and missingness.
2. Detect
Flag anomalies, duplicates, and rule violations.
3. Investigate
Check source systems and domain context.
4. Decide
Correct, retain, exclude, impute, or flag.
5. Document
Record rules, changes, and remaining limitations.

Quality Scenario: Heart Rate

A heart_rate column contains 72, -1, 0, 200, and a blank value.

  • -1 and possibly 0 violate validity rules and may be inaccurate.
  • The blank value creates a completeness problem.
  • 200 may be valid in a specific clinical context; investigate before labeling it an error.
  • Do not automatically delete every unusual value. Use domain knowledge and preserve an audit trail.

3. What Does Each Variable Mean?

Measurement scales define the operations, summaries, and comparisons that are defensible.

First Split: Categorical or Numeric?

Categorical

Values represent labels, groups, or ordered levels.

Subtypes: nominal and ordinal

Numeric

Values represent quantities for which arithmetic may be meaningful.

Subtypes: interval and ratio

Measurement scales and appropriate analysis
Scale Ordered? Equal Differences? True Zero? Examples Useful Summaries Typical Visuals
Nominal
Categorical		 No No No Blood type, device type, ZIP code, patient ID Counts, proportions, mode; χ2 procedures Bar chart, mosaic plot
Ordinal
Categorical		 Yes Not guaranteed No Triage level, education level, satisfaction 1-5 Counts, median, percentiles, IQR; rank procedures Ordered bars, median/IQR plots
Interval
Numeric		 Yes Yes No Temperature in C or F, calendar year Mean, standard deviation, correlation; ratios are not meaningful Histogram, line chart
Ratio
Numeric		 Yes Yes Yes Age, weight, income, distance, elapsed time, counts All arithmetic, including ratios when appropriate Histogram, box plot, violin plot, scatterplot

Nominal: Different, Not Ordered

Blood type categories differ, but A+ is not "greater than" O-.

Common mistake: Treating numeric-looking identifiers such as ZIP codes as quantities.

Ordinal: Ordered, Unequal Gaps

Triage levels have a meaningful sequence, but the distance from "non-urgent" to "urgent" is not guaranteed to equal the distance from "urgent" to "emergent."

Common mistake: Assuming integer codes automatically create equal numerical spacing.

Likert caution: A single 1-5 item is ordinal. Means are commonly reported, but medians, IQRs, and rank-based methods are safer when the distribution is skewed or the response scale is coarse. A validated multi-item composite may sometimes be treated as approximately interval, but that decision should be justified and checked for robustness.

Interval: Equal Differences, No True Zero

A 5-degree change in Celsius has a consistent meaning, but 20 C is not twice as hot as 10 C.

Ratio: Equal Differences and True Zero

Zero ER visits means no visits. Four visits are twice as many as two visits.

Numeric Variables: Discrete or Continuous?

Discrete Counts
  • Arise from counting: 0, 1, 2, and so on.
  • Examples: visits, purchases, readmissions, defects.
  • Fractions are generally not meaningful for the individual count.
  • Counts are usually ratio-scale variables because zero means none.
Continuous Measurements
  • Arise from measurement and can, conceptually, take values within a range.
  • Examples: height, laboratory values, duration, and income.
  • Observed precision depends on the measuring instrument.
  • A continuous phenomenon may still be stored as an integer.
Concept over storage: Heart rate may be stored as an integer, but it measures a continuous physiological phenomenon. Classify the concept, not merely the file's dtype.

Common Classification Traps

Variables that are commonly misclassified
VariableIt Looks LikeIt Is Better Treated AsWhy

Patient IDAn integerNominal identifierThe value identifies a record rather than measuring an amount.
Satisfaction 1-5NumericOrdinalThe levels are ordered, but equal spacing is not guaranteed.

4. From Type to Analytical Decision

Use the meaning of the variable to guide summaries, visualizations, and preprocessing choices.

Decision guide by variable type
Variable Type Useful Summaries Typical Visualizations Common Encoding or Preparation Key Caution
Nominal Counts, percentages, mode Bar chart, mosaic plot One-hot encoding; group rare levels only with justification Do not invent an order.
Ordinal Counts, median, percentiles, IQR Ordered bar chart, median/IQR display Ordered categorical dtype or documented ordinal codes Do not assume equal gaps without evidence.
Interval / Ratio Continuous Mean and SD when suitable; median and IQR for skewed data Histogram, box plot, violin plot, scatterplot Keep numeric; standardize for selected models; consider justified transformations Check skew, outliers, units, and precision.
Ratio Count Counts, rates, proportion of zeros, median, IQR Bar plot, histogram, count distribution Keep as a nonnegative integer; preserve exposure or time-at-risk information Counts are often skewed and may contain many zeros.

Encoding Example: Membership Tier

Suppose member_tier has the ordered levels Bronze, Silver, Gold, and Platinum. The right representation depends on the analytical purpose and the model.

Corrected one-hot and ordinal encoding example
Original Silver Gold Platinum Ordinal Code
Bronze0000
Silver1001
Gold0102
Platinum0013

With drop="first", Bronze is the reference category and is represented by zeros in the three generated dummy columns. It is not a fourth generated column.

One-Hot Representation

Creates separate indicator columns and does not impose a numerical distance between categories.

Common use: nominal variables and models that should not infer order from a single integer code.

Ordinal Representation

Maps ordered levels to documented codes that preserve rank.

Caution: Codes such as 0, 1, 2, 3 may imply equal spacing to some models. Confirm that the model and interpretation are appropriate.

Different outcome types often lead to different model families. Count outcomes may motivate Poisson, negative binomial, or zero-inflated models. Continuous outcomes may motivate linear or generalized additive models, sometimes with transformations for heavy tails.

High-cardinality categories may motivate target or mean encoding, but these methods require careful cross-validation to prevent information leakage. Treat these as advanced topics rather than default Module 1 techniques.

5. Guided Python Lab

Apply the conceptual decisions to one small dataset using pandas and scikit-learn.

Lab goal: Inspect the data first, document what each variable means, and only then assign dtypes or encodings. Technical transformations should follow the conceptual classification - not replace it.

Step 1: Create and Inspect the Dataset

import pandas as pd

encounters = pd.DataFrame({
    "patient_id": ["P1001", "P1002", "P1003", "P1004", "P1005"],
    "sex": ["F", "M", "F", "F", "M"],
    "triage_level": ["Non-urgent", "Urgent", "Emergent", "Urgent", "Non-urgent"],
    "temperature_c": [37.0, 39.1, 38.2, 36.8, 37.4],
    "er_visits": [0, 3, 2, 5, 1],
    "member_tier": ["Bronze", "Silver", "Gold", "Platinum", "Silver"]
})

print(encounters.head())
print(encounters.info())
print(encounters.isna().sum())
print(encounters.nunique())

Before You Transform Anything

  • patient_id: nominal identifier
  • sex: nominal category as defined in this dataset
  • triage_level: ordinal category
  • temperature_c: interval, conceptually continuous
  • er_visits: ratio-scale discrete count
  • member_tier: ordinal category

Step 2: Assign Meaningful pandas Dtypes

from pandas.api.types import CategoricalDtype

# Nominal categories
encounters["sex"] = encounters["sex"].astype("category")

# Ordered categorical variables
triage_order = CategoricalDtype(
    categories=["Non-urgent", "Urgent", "Emergent"],
    ordered=True
)
tier_order = CategoricalDtype(
    categories=["Bronze", "Silver", "Gold", "Platinum"],
    ordered=True
)

encounters["triage_level"] = encounters["triage_level"].astype(triage_order)
encounters["member_tier"] = encounters["member_tier"].astype(tier_order)

# Keep identifiers as strings rather than quantities
encounters["patient_id"] = encounters["patient_id"].astype("string")

print(encounters.dtypes)

Step 3: Encode Categories and Scale Selected Numeric Features

from sklearn.preprocessing import OneHotEncoder, OrdinalEncoder, StandardScaler

# One-hot encode the nominal variable.
# With two levels and drop="first", one indicator column is produced.
one_hot = OneHotEncoder(drop="first", sparse_output=False, handle_unknown="ignore")
sex_matrix = one_hot.fit_transform(encounters[["sex"]])
sex_columns = one_hot.get_feature_names_out(["sex"])
encounters[sex_columns] = sex_matrix

# Encode membership tier with an explicit documented order.
tier_encoder = OrdinalEncoder(
    categories=[["Bronze", "Silver", "Gold", "Platinum"]]
)
encounters["tier_code"] = (
    tier_encoder.fit_transform(encounters[["member_tier"]])
    .astype(int)
)

# Standardization may be useful for models that are sensitive to scale.
# Fit on training data only in a real predictive workflow.
scaler = StandardScaler()
numeric_features = ["temperature_c", "er_visits"]
scaled = scaler.fit_transform(encounters[numeric_features])
encounters[["temperature_z", "er_visits_z"]] = scaled

print(encounters)
Prevent leakage: In predictive modeling, fit encoders and scalers on the training data and apply the fitted transformations to validation and test data. Do not fit preprocessing steps on the full dataset before evaluation.

Step 4: Flatten Semi-Structured JSON

from pandas import json_normalize

records = [
    {
        "patient_id": "P1001",
        "metrics": {"heart_rate": 72, "steps": 500},
        "location": {"lat": 36.07, "lon": -79.79}
    },
    {
        "patient_id": "P1002",
        "metrics": {"heart_rate": 65, "steps": 900, "spo2": 0.97}
    }
]

flat = json_normalize(records, sep="_")
print(flat)

# Expected columns include:
# patient_id, metrics_heart_rate, metrics_steps, metrics_spo2,
# location_lat, and location_lon

Step 5: Add Basic Quality Checks

# Completeness
print(encounters.isna().sum())

# Uniqueness of the identifier
assert encounters["patient_id"].is_unique, "Duplicate patient_id values found"

# Simple validity checks for this teaching dataset
assert encounters["temperature_c"].between(30, 45).all(), "Review temperature range"
assert encounters["er_visits"].ge(0).all(), "ER visits cannot be negative"

# Frequency review for categorical values
print(encounters["triage_level"].value_counts(dropna=False).sort_index())
Lab takeaway: The analytical classification determines what a variable means; the pandas dtype and encoding determine how software represents that meaning for a particular task.

6. Database Storage Preview

Connect analytical meaning to practical storage without treating the two as identical.

Measurement scale informs analysis; precision and application requirements inform storage. For example, currency may require exact NUMERIC arithmetic, while an approximate physical measurement may reasonably use a floating-point type.
Suggested PostgreSQL storage types by data purpose
Data PurposePossible PostgreSQL TypePractical Note
IdentifierBIGINT, UUID, or TEXTDo not perform arithmetic merely because an identifier contains digits.
Nominal labelTEXT, VARCHAR, or lookup-table keyUse a documented domain and consider a reference table.
Ordered categorySMALLINT plus lookup table, or constrained TEXTStore both the label and the intended order in a documented design.
CountINTEGER or BIGINTAdd a nonnegative constraint when the domain requires it.
Exact decimal, such as moneyNUMERIC(p,s)Use exact arithmetic rather than floating-point approximations.
Approximate measurementREAL or DOUBLE PRECISIONSelect precision based on the instrument and application.
Calendar or event timeDATE, TIME, or TIMESTAMPUse dedicated temporal types so calendar meaning is preserved.

Short Constraint Example

CREATE TABLE encounters (
    encounter_id BIGSERIAL PRIMARY KEY,
    patient_id TEXT NOT NULL,
    encounter_date DATE NOT NULL,
    triage_level TEXT NOT NULL
        CHECK (triage_level IN ('Non-urgent', 'Urgent', 'Emergent')),
    temperature_c DOUBLE PRECISION
        CHECK (temperature_c BETWEEN 30 AND 45),
    er_visits INTEGER NOT NULL
        CHECK (er_visits >= 0),
    total_charge NUMERIC(12, 2)
        CHECK (total_charge >= 0)
);

7. Applied Cases

Classify variables first, then justify summaries, visualizations, encodings, and storage choices.

Variables: diagnosis code, pain score 0-10, temperature C, age, comorbidity count, length of stay, and 30-day readmissions.

Your Task

  1. Classify each variable by measurement scale.
  2. Identify which numeric variables are counts and which are measurements.
  3. Choose one appropriate visualization for pain score and one for length of stay.
  4. Recommend an encoding for diagnosis code.

  • Diagnosis code: nominal; commonly represented with categorical indicators or domain-aware grouping.
  • Pain score: ordinal; use ordered bars and consider medians/IQRs.
  • Temperature C: interval and conceptually continuous.
  • Age: ratio and conceptually continuous.
  • Comorbidity count and readmissions: ratio-scale discrete counts.
  • Length of stay: ratio; measured time may be conceptually continuous even when reported in whole days.
  • Useful visuals include an ordered bar chart for pain and a box, violin, or histogram for length of stay.

Variables: device type, membership tier, session duration, weekday, purchases in 30 days, and revenue.

Your Task

  1. Classify each variable by measurement scale.
  2. Select encodings for device type, weekday, and membership tier.
  3. Choose a visualization for purchases and another for session duration.
  4. Recommend SQL storage for revenue.

  • Device type and weekday: nominal. One-hot encoding is a common starting point.
  • Membership tier: ordinal when the business rules define a meaningful order.
  • Session duration and revenue: ratio and conceptually continuous.
  • Purchases: ratio-scale discrete count.
  • Purchases can be shown with a count distribution; session duration may use a histogram or box plot and may require a log scale when strongly right-skewed.
  • Store currency in an exact NUMERIC field and store a documented currency code separately.

8. Assessment and Closure

Move from recognition to justification and then to applied decision-making.

Checkpoint 1: Recognition

Classify each variable as nominal, ordinal, interval, or ratio. For numeric variables, also state whether it is a count or measurement.

  1. Education level: HS, BS, MS, PhD
  2. Body temperature in C
  3. Monthly income in USD
  4. Number of ER visits in the last year
  5. Customer satisfaction from 1 to 5
  6. ZIP code

Checkpoint 2: Justification

  1. Explain why ZIP code is not a ratio variable even when it is stored as an integer.
  2. Explain why temperature in Celsius permits meaningful differences but not meaningful ratios.
  3. Explain the risk of encoding unordered categories as 0, 1, 2, and 3.

Checkpoint 3: Application

A dataset contains patient_id, triage_level, heart_rate, encounter_status, and length_of_stay.

  1. Identify two quality checks you would run.
  2. Classify three of the variables.
  3. Select one summary and one visualization.
  4. Recommend one encoding or storage decision.

Sample Answers

  • Education level: ordinal.
  • Temperature C: interval, continuous measurement.
  • Income: ratio, continuous measurement.
  • ER visits: ratio, discrete count.
  • Satisfaction 1-5: ordinal.
  • ZIP code: nominal.

ZIP codes label areas; subtraction or ratios do not have a meaningful interpretation. Celsius has equal units, but zero is not the absence of temperature. Integer codes for nominal categories can cause a model to infer an order or distance that the data does not contain.

Possible applied checks include missingness, duplicate IDs, allowed encounter statuses, plausible heart-rate ranges, and nonnegative length of stay. Triage level is ordinal; patient ID is nominal; heart rate and length of stay are ratio-scale measurements. An ordered bar chart can summarize triage, while a histogram or box plot can summarize length of stay.

Five Key Takeaways

1. Data organization and variable measurement are different layers of classification.
2. Quality must be assessed before sophisticated analysis can be trusted.
3. Measurement scale determines which comparisons and summaries are defensible.
4. A software dtype or SQL type does not, by itself, define analytical meaning.
5. Good preprocessing follows a documented conceptual decision and is fitted carefully to avoid leakage.
