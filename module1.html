A guided tour through data organization, quality, measurement scales, and the decisions that transform raw data into trusted insights.

Part 1: How Data Is Organized

Data comes in three broad forms, and the way it’s organized dictates how we store, query, and clean it. Think of it as the “container” that holds your information.

Structured Data

Structured data lives in tables with rows and columns, like an Excel spreadsheet or a relational database table. Every column has a defined type (e.g., integer, date, text), and the schema is known ahead of time. This makes it easy to query with SQL and to validate with constraints.

  • Where you find it: Relational databases (PostgreSQL, MySQL), data warehouses (Snowflake, BigQuery), CSV files, Parquet files.
  • Examples: EHR tables (patients, encounters), retail orders, financial transactions.
  • Prep focus: Ensuring correct data types, handling NULLs, maintaining referential integrity, deduplication.

Semi‑Structured Data

Semi‑structured data has a flexible format, often self‑describing (like JSON or XML). It doesn’t enforce a rigid schema – some fields may be missing, and the same field might hold a number in one record and a string in another (though hopefully not!).

  • Where you find it: REST API responses, log files, IoT sensor streams, NoSQL document stores (MongoDB).
  • Prep focus: Parsing, flattening nested objects, inferring schema, and aligning units/keys across records.
{
  "patient_id": "P1001",
  "timestamp": "2025-07-28T10:30:00Z",
  "metrics": {"hr": 72, "steps": 500, "sleep_hours": 7.5},
  "location": {"lat": 36.07, "lon": -79.79}
}

Notice how sleep_hours could be missing in another record, or an extra field like spo2 could appear. That’s the “semi” part.

Unstructured Data

Unstructured data has no predefined model at all – think of the text in a physician’s note, the pixels in an X‑ray image, or the waveform of a customer call. It’s the richest but also the hardest to analyse directly with traditional SQL.

  • Where you find it: Clinical notes, PDFs, DICOM medical images, audio recordings, social media posts.
  • Prep focus: Converting raw content into structured features using NLP (tokenization, named entity recognition), computer vision, or automatic speech recognition.
NIST definition: Structured data has a well‑defined model; unstructured data does not; semi‑structured data sits in between.

Volume, Velocity, and Variety (the 3 Vs)

Doug Laney (Gartner) coined the “3 Vs” to describe big data challenges:

  • Volume – sheer amount of data (terabytes/petabytes).
  • Velocity – speed at which new data arrives (real‑time streams).
  • Variety – the mix of structured, semi‑structured, and unstructured sources.

In this course, you’ll deal most with variety: learning to handle all three shapes of data and prepare them for analytics.

Part 2: Is the Data Trustworthy?

Before you analyse anything, ask: “Can I trust this data?” Six universally‑recognised quality dimensions help you answer that.

Six Data‑Quality Dimensions

DimensionQuestionExample IssueHow to Check (SQL/Python idea)
AccuracyIs the data correct?Weight = 500 kg (typo)Range checks (weight between 0‑400)
CompletenessAre all required fields present?20% of blood types are NULLCOUNT(*) - COUNT(blood_type)
ConsistencyIs the same info uniform across sources?Date of birth stored as 1985-05-15 and 05/15/85Compare column formats, use regex
TimelinessIs the data fresh enough for the task?Using last year’s census for a real‑time dashboardCheck MAX(timestamp) vs. current date
UniquenessAre there duplicate records?Same patient appears twice with different IDsGroup by natural key, count > 1
ValidityDoes data obey defined rules?Gender column contains “Unknown” when only M/F allowedSELECT DISTINCT sex FROM patients

Data‑Profiling Workflow

Profiling is the systematic examination of your data. A simple but effective five‑step recipe:

  1. Scan – row counts, column names, inferred types (df.info(), df.shape).
  2. Missingness – percentage of NULLs per column (df.isnull().mean()*100).
  3. Uniqueness – duplicate rows, primary key violations (df.duplicated()).
  4. Distributions – min, max, mean, quartiles, distinct counts (df.describe(include='all')).
  5. Rules – check domain constraints (e.g., age > 0, blood type in allowed list).
Pro tip: Profiling should be your first step on any new dataset, before you write a single line of cleaning code.

Guided Quality Scenario

Imagine our running dataset gains a heart_rate column with these values: 72, -1, 0, 200, and a blank cell. Which dimensions are violated?

  • Accuracy – -1 and 0 are physiologically impossible for a living person; 200 is suspiciously high.
  • Completeness – the blank cell means missing data.
  • Validity – heart rate should be a positive integer, not negative.

What would you do? Check ranges, possibly replace impossible values with NULLs, and flag those records for further investigation. (We’ll dive deep into cleaning in Module 9.)

Part 3: What Does Each Variable Mean?

Now we shift from the container to the contents. Every column in your dataset carries a measurement scale. The scale determines which operations are mathematically defensible.

Categorical vs. Numeric – The First Split

At the highest level, variables are either categorical (labels or groups) or numeric (quantities). But be careful: ZIP codes look numeric yet are categories; a satisfaction score of 1‑5 is categorical (ordinal) even though it’s stored as a number.

Nominal Scale

  • Definition: Unordered categories – no ranking.
  • Examples: Blood type (A+, O-), device type, eye color, country.
  • Valid stats: Counts, mode, proportions, chi‑square tests.
  • Visuals: Bar chart (sorted by frequency), mosaic plot.
  • Encoding: One‑hot (dummy) encoding; group rare categories into “Other”.

Ordinal Scale

  • Definition: Ordered categories, but the gaps between levels are unknown or unequal.
  • Examples: Education level (HS, BS, MS, PhD), satisfaction survey (1‑5), movie ratings (1 star to 5 stars).
  • Valid stats: Median, interquartile range (IQR), percentiles, rank‑based tests (Mann‑Whitney).
  • Visuals: Ordered bar chart, median‑IQR dot plot.
  • Caution: Reporting a mean of “3.2” for a Likert item assumes equal gaps – if you do it, document the assumption and check robustness with non‑parametric tests.
  • Encoding: Ordinal integer mapping with a documented order; or treat as nominal with one‑hot if order is uncertain.

Interval Scale

  • Definition: Numeric, equal differences between values, but no true zero (zero does not mean “none”).
  • Examples: Temperature in °C or °F, calendar year, pH.
  • Valid stats: Mean, standard deviation, correlation – ratios are meaningless (e.g., 20°C is not “twice as hot” as 10°C).
  • Visuals: Histogram, line chart.

Ratio Scale

  • Definition: Numeric, equal differences, true zero (zero means absence).
  • Examples: Age, weight, income, distance, counts (number of visits).
  • Valid stats: All arithmetic operations, including ratios (e.g., $100 is twice $50).
  • Visuals: Histogram, box plot, violin plot, scatter plot.

Discrete vs. Continuous (Both Usually Ratio)

Numeric variables can be further divided by how they are generated:

Discrete (Counts)

Arises from counting. Only takes integer values (0,1,2,…). Examples: ER visits, purchases, number of defects. Usually a ratio scale. Model with Poisson, Negative Binomial; check for zero‑inflation.

Continuous (Measurements)

Arises from measuring. Can take any value within an interval (though instruments limit precision). Examples: height, lab results, time spent. Linear regression, GAMs, log transforms for heavy tails.

Edge case: Heart rate stored as an integer is still a continuous phenomenon – don’t let the storage type fool you.

Common Classification Mistakes 🚩

  • Treating ZIP codes as numeric – a mean ZIP code is nonsense.
  • Using mean for skewed ordinal data – better to report median and IQR.
  • Storing currency as FLOAT – floating‑point errors can cost cents (or millions). Use DECIMAL/NUMERIC.
  • Assuming all integers are discrete – always think about the underlying phenomenon.

Part 4: From Type to Decision

Now that you can classify a variable, how do you choose the right summary, chart, and encoding?

Summary Statistics at a Glance

ScaleCenterSpreadRelationship
NominalModeProportionChi‑square
OrdinalMedianIQRRank correlation
IntervalMeanSDPearson r
RatioMean or medianSD or IQRPearson r (all arithmetic OK)

Visualization Cheat Sheet

  • Nominal: Bar chart (sorted by frequency); pie charts are often harder to read.
  • Ordinal: Ordered bar chart; median‑IQR dot plot to show spread.
  • Interval / Ratio: Histogram for shape, box/violin for comparing groups, scatter for two variables.

Encoding: Turning Categories into Numbers

Most machine‑learning models require numeric inputs. Here’s a practical mapping:

ScaleRecommended EncodingWhy?
NominalOne‑hot (drop first category)No ordinal relationship; avoids dummy variable trap.
OrdinalInteger mapping or one‑hotInteger preserves order; one‑hot ignores it (safe if order is weak).
Interval / RatioKeep as numeric; standardize (z‑score) for distance‑based modelsPreserves magnitude; scaling prevents features from dominating.

Example: member_tier {Bronze, Silver, Gold, Platinum} – ordinal map → 0,1,2,3; one‑hot creates three columns (Silver, Gold, Platinum) with Bronze as reference.

Decision Guide – A Simple Flowchart

Is there a natural order?

  • No → Nominal → one‑hot encoding.
  • Yes → Are the gaps equal?
    • No → Ordinal → ordered integer (carefully) or one‑hot.
    • Yes → Does zero mean “none”?
      • No → Interval → keep numeric, scale.
      • Yes → Ratio → keep numeric, all operations valid.

Part 5: Guided Python Lab

Let’s walk through the essential steps you’ll perform on almost any tabular dataset using pandas and scikit‑learn.

1. Inspect and Profile

We start by loading the data and getting a quick overview.

import pandas as pd
df = pd.read_csv('patients.csv')
print(df.shape)           # rows, columns
print(df.info())          # column names, non-null counts, dtypes
print(df.describe(include='all'))  # stats for all columns
print(df.isnull().mean()*100)     # percent missing per column

2. Assign pandas Dtypes

Setting correct types early prevents silent errors later.

# Nominal: convert to category (saves memory)
df['sex'] = df['sex'].astype('category')
df['blood_type'] = df['blood_type'].astype('category')

# Ordinal: define the order explicitly
from pandas.api.types import CategoricalDtype
edu_order = CategoricalDtype(categories=['HS','BS','MS','PhD'], ordered=True)
df['edu_level'] = df['edu_level'].astype(edu_order)

3. Encode Categories

Convert categories to numbers for modeling.

from sklearn.preprocessing import OrdinalEncoder, OneHotEncoder

# Ordinal encoding (respects order)
enc = OrdinalEncoder(categories=[['Bronze','Silver','Gold','Platinum']])
df['tier_code'] = enc.fit_transform(df[['member_tier']]).astype(int)

# One-hot encoding (drop='first' to avoid dummy trap)
ohe = OneHotEncoder(drop='first', sparse_output=False)
gender_oh = ohe.fit_transform(df[['gender']])
# Add to DataFrame (F is dropped, M column remains)
df['gender_M'] = gender_oh  # 1 if male, 0 if female

4. Scale Numeric Features

Many models (SVM, k‑NN, neural nets) expect features on a similar scale. Standardization (z‑score) is a common choice.

from sklearn.preprocessing import StandardScaler
scaler = StandardScaler()
num_cols = ['age', 'temp_c', 'er_visits']
df[[c + '_z' for c in num_cols]] = scaler.fit_transform(df[num_cols])
# Now each scaled column has mean=0, std=1

5. Normalize JSON (Semi‑Structured)

When you receive nested JSON, flatten it into a table.

from pandas import json_normalize
records = [
  {"patient_id":"P1001","metrics":{"hr":72,"steps":500},"location":{"lat":36.07,"lon":-79.79}},
  {"patient_id":"P1002","metrics":{"hr":65,"steps":900,"spo2":0.97}}
]
flat = json_normalize(records, sep='_')
print(flat.columns)  # patient_id, metrics_hr, metrics_steps, metrics_spo2, location_lat, location_lon

Part 6: Database Storage Preview

When you store data in a relational database, the measurement scale suggests the right SQL type and the constraints that protect integrity.

Analytical Meaning → SQL Type

ScaleRecommended SQL TypeWhy?
NominalVARCHAR / TEXTFlexible; add CHECK to limit to allowed values.
OrdinalSMALLINT or VARCHAR + CHECKSmall integer with a lookup table, or text with constraint.
IntervalINTEGER / FLOAT / DATENumerical precision; DATE/TIMESTAMP for calendar values.
Ratio (continuous)DECIMAL / NUMERICExact arithmetic – mandatory for money.
Ratio (count)INTEGER / BIGINTWhole numbers; add CHECK(value >= 0).

Basic Constraints in Action

-- A well‑constrained orders table
CREATE TABLE orders (
    order_id BIGSERIAL PRIMARY KEY,
    customer_id BIGINT NOT NULL,
    order_date DATE NOT NULL,
    total_amount NUMERIC(12,2) NOT NULL CHECK (total_amount >= 0),
    currency CHAR(3) NOT NULL CHECK (currency IN ('USD','EUR','GBP'))
);

-- Lookup table for ordinal tiers
CREATE TABLE membership_tier (
    tier_code SMALLINT PRIMARY KEY,
    tier_label VARCHAR(20) UNIQUE NOT NULL,
    tier_rank SMALLINT NOT NULL CHECK (tier_rank BETWEEN 1 AND 4)
);

These constraints guarantee that no negative amounts or invalid currencies sneak into your database.

Part 7: Applied Cases

Let’s put the whole framework to work in two realistic scenarios.

🏥 Healthcare

Goal: Predict patient length of stay (LOS) in days.

  • Outcome: LOS → ratio (discrete count of days).
  • Predictors:
    • Diagnosis code (nominal) → one‑hot encoding.
    • Pain score 0‑10 (ordinal) → treat as ordinal, maybe integer encode.
    • Temperature °C (interval) → keep numeric, scale.
    • Age (ratio) → keep numeric, scale.
    • Comorbidity count (ratio discrete) → consider Poisson model.
  • Quality check: Look for impossible values (negative pain, age > 120).
  • Visual: Box plot of LOS by diagnosis group.
🛒 E‑Commerce

Goal: Predict number of purchases in the next 30 days.

  • Outcome: Purchases → ratio (count).
  • Predictors:
    • Device type (nominal) → one‑hot.
    • Membership tier (ordinal) → ordinal integer mapping.
    • Session duration (ratio) → log transform if skewed.
    • Weekday (nominal cyclical) → one‑hot or sine/cosine encoding.
  • SQL tip: Store revenue in NUMERIC, not FLOAT.
  • Visual: Scatter plot of session duration vs. purchases.

📌 Key Takeaways

  • Data organization (structured/semi/unstructured) guides your initial toolset.
  • Always profile your data using the six quality dimensions before analysis.
  • Measurement scales (nominal, ordinal, interval, ratio) are the backbone of all valid statistical and visualization choices.
  • Encoding must align with both the scale and the model’s assumptions.
  • Database types and constraints preserve data meaning and integrity at the storage level.
